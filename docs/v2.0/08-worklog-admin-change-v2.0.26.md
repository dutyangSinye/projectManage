# 芯烨工时管理系统后台工时管理修改说明

> 版本：v2.0.26 ｜ 日期：2026-08-26 ｜ 状态：已完成，待业务 UAT

## 1. 修改目标

增加系统管理员专用的“工时管理”页面，列出全体用户的工时记录，并支持按日期范围、一级部门、填报人员筛选；管理员可修改和删除任意工时。同步修复并验证项目管理的新增、编辑、查询、软删除流程。

## 2. 权限与数据规则

- “工时管理”菜单、接口和操作按钮只对 `SYSTEM_ADMIN_USER_IDS` 中的当前用户开放。
- 普通员工、审批人和报表查看者不能读取全量工时，也不能调用管理员修改/删除接口。
- 编辑管理员工时时保留当前审批状态和审批任务，不自动重新发送通知；若修改已通过工时，写入审计日志。
- 删除采用物理删除工时及其审批任务、通知记录，并写入工时删除审计；删除前由前端二次确认。
- 已通过、审批中、草稿和已驳回记录均可在后台查询；日期按工时开始日期到结束日期筛选。
- 部门筛选按工时所属项目的一级部门计算；人员筛选按实际填报人。

## 3. 接口契约

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/admin/worklogs` | GET | 管理员全量工时列表；支持 `period_start`、`period_end`、`department_name`、`user_id`、`status`、`keyword` |
| `/api/v1/admin/worklogs/{id}` | PATCH | 管理员修改项目、阶段、类型、工作状态、日期、天数和描述；校验项目可填报状态和天数单位 |
| `/api/v1/admin/worklogs/{id}` | DELETE | 管理员删除工时及其审批关联记录，并保留审计事件 |

列表返回工时快照、填报人、一级部门、审批人、审批状态、提交时间和处理时间，前端提供分页展示所需的总数与当前记录。

## 4. 页面交互

- 管理菜单中增加“工时管理”，仅管理员导航可见。
- 默认显示全部状态和最近数据；筛选条件采用日期范围、一级部门下拉、人员下拉和关键词，点击“查询”后统一刷新列表。
- 修改使用弹窗；保存成功后刷新列表，失败显示后端错误。
- 删除使用确认弹窗，成功后从列表移除并提示“已删除”。
- 移动端表格允许横向滚动，操作按钮保持可触达。
- 项目管理编辑弹窗打开时加载当前项目完整字段，保存后刷新项目列表并保持编辑值；新增、查询、编辑、软删除均显示明确反馈。

## 5. 验收标准

1. 管理员可看到“工时管理”，普通用户看不到。
2. 管理员可以按日期、部门、人员和关键词筛选全体工时，筛选结果数量准确。
3. 管理员编辑工时后，列表、个人工时和报表读取到最新字段；审批状态和历史审批任务不被意外重置。
4. 管理员删除工时后，相关审批任务和通知不再出现，审计日志保留删除事件。
5. 非管理员调用三个接口均返回 `403 ADMIN_REQUIRED`。
6. 项目新增、列表查询、编辑、软删除接口和页面操作全部通过，项目软删除后不出现在可填报列表但历史工时仍可查询。
7. 前端生产构建、后端编译、核心审批/报表/项目回归通过。

# 芯烨工时管理系统产品需求文档

> 版本：v2.0.30 ｜ 日期：2026-08-27 ｜ 状态：已修订，开发中

## 1. 产品目标

让员工用最少步骤提交一项具体工作内容，让项目审批人集中在系统内逐条处理，并通过飞书机器人及时收到待审批提醒。系统不依赖真实飞书审批模板，不生成周期性审批单。

## 2. 用户与场景

| 用户 | 主要任务 |
|---|---|
| 员工 | 选择项目、日期、阶段、工时和工作描述；默认直接提交；处理驳回后重新提交 |
| 项目审批人 | 查看分配给自己的待审工时；通过或填写原因驳回；催办/查看历史 |
| 项目管理员 | 新增、编辑、查询、删除项目；配置项目负责人、审批人、上级领导、可填报状态和项目基本信息 |
| 管理人员 | 按周期、项目、部门、人员查看已审批工时和审批积压 |

## 3. 核心规则

1. 一条工时填报单只描述一个项目、一个日期范围内的一项具体工作内容。
2. 新建工时默认执行“保存并提交”；同时提供“仅保存草稿”。
3. 每条工时独立生成一个本地审批任务，禁止把多条工时合并成一张审批单。
4. 项目审批人从项目关联用户中读取，必须保存 `approver_user_id`；姓名仅为快照。
5. 当项目审批人就是当前填报人时，改用项目配置的上级领导审批；上级领导必须有效、启用且不能与填报人相同。
6. 上级领导未配置、停用或仍是当前填报人时禁止提交，返回 `APPROVER_SELF_NO_LEADER`。
7. 提交后工时只读；审批人必须进入系统操作，飞书消息只提供提醒和链接。
8. 驳回必须填写原因；驳回后员工可修改并重新提交，重新提交创建新的审批版本并保留旧记录。
9. 通过和锁定的工时不可普通修改；更正流程不纳入本次 P0。
10. 周期仅用于筛选、汇总、月结锁账和导出，不触发审批任务生成。
11. 报表默认统计 `APPROVED`、`LOCKED`；`PENDING_APPROVAL` 和 `REJECTED` 单独展示。
12. 所有提交、通知、通过、驳回、重新提交和项目审批人变更写入审计记录。
13. 项目负责人、审批人和上级领导只能从飞书组织架构同步的启用用户中选择，不允许手工输入人员姓名。
14. 项目删除采用软删除；有工时或审批历史的项目不物理删除，历史快照继续可查。
15. 项目部门只能从飞书组织架构同步的启用部门中选择，不允许手工输入部门名称。
16. 工时项目选择支持按项目名称或编码筛选，项目选项不展示审批人信息；审批链仍由后端在提交时解析。
17. 工时单位固定为“天”，填报、审批、列表和报表统一按天展示；历史小时数据仅兼容读取，不再允许新建或编辑为小时。
18. 组织同步入口位于“集成与通知”，仅 `SYSTEM_ADMIN_USER_IDS` 配置的系统管理员可见和调用。
19. 提交时若项目保存的审批人本地 ID 已失效，系统按审批人 `open_id` 或唯一的启用用户姓名重新绑定；姓名重复时禁止猜选并返回明确错误。
20. 员工在“我的工时”查看已提交记录时，必须能看到该工时的完整快照、当前审批状态、审批意见、提交/处理时间和最近一次飞书通知结果；飞书通知失败时展示可排查的原因，不得伪装成审批失败。

## 4. 功能范围

| 编号 | 功能 | 优先级 | 验收要点 |
|---|---|---|---|
| F1 | 飞书用户/部门身份 | P0 | 当前用户与审批人通过用户 ID 识别；姓名变化不影响历史记录 |
| F1.1 | 飞书 OAuth 登录 | P0 | 在飞书内打开系统时使用飞书账号登录；未登录不能访问业务接口；登录用户必须匹配已同步的启用用户 |
| F2 | 项目管理 CRUD 与审批链配置 | P0 | 项目可新增、编辑、查询、软删除；负责人、审批人和上级领导均从飞书启用用户中选择；审批人是填报人时转由上级领导审批 |
| F2.1 | 飞书组织用户同步 | P0 | 项目人员选择只展示已同步且启用的组织用户；同步失败不清空现有人员 |
| F3 | 单条工时填报 | P0 | 默认保存并提交；项目支持名称/编码筛选且选项不带审批人；草稿可编辑/删除；提交后只读；单位固定为天 |
| F4 | 本地审批任务 | P0 | 一条工时对应一条审批任务；状态、意见、时间完整可查 |
| F5 | 审批处理 | P0 | 审批人可通过或驳回；驳回原因必填；非审批人不能操作 |
| F6 | 飞书消息通知 | P0 | 提交后按审批人的 `open_id` 发送单条应用私聊通知；失败可重试；通知包含系统链接 |
| F7 | 个人工作台 | P0 | 展示草稿、待审批、驳回和本月已通过数量 |
| F8 | 审批工作台 | P0 | 待我审批列表、详情、筛选、催办和处理记录 |
| F9 | 周期报表与锁账 | P1 | 周期只作汇总维度；锁账后明细不可修改；管理报表使用 ECharts 展示项目投入、人员分布、项目阶段、审批状态、项目阶段占比和工时类型；支持按一级部门和自定义时间导出天数明细；统一按天统计 |
| F10 | 多维表迁移/兼容 | P1 | 可保留历史记录和来源 ID；新流程不依赖多维表审批字段 |

## 5. 状态模型

```text
DRAFT → PENDING_APPROVAL → APPROVED
                       ↘ REJECTED → DRAFT（修改）→ PENDING_APPROVAL
APPROVED → LOCKED（周期锁账）
```

审批任务状态与工时状态同步，但审计记录不可覆盖。通知状态单独维护，不影响审批状态。

## 6. 非目标

- 本版本不创建真实飞书审批实例，不接入飞书审批回调；身份登录在飞书内通过 H5 SDK 获取授权码并由后端换取用户身份。
- 本版本不按周/月自动生成审批单，不支持多条工时批量合并审批。
- 本版本不实现薪资、考勤、绩效、请假、费用报销和复杂多级审批。
- 本地 mock 模式不代表真实通讯录；生产环境需配置飞书应用凭证并执行组织架构同步。

## 7. 成功标准

- 员工从新建到提交最多两步，提交后能看到审批人和本地单号。
- 每条已提交工时都能在审批人待办中独立出现。
- 审批通过、驳回、重新提交不会产生重复审批任务或重复通知任务。
- 非审批人无法通过接口处理任务；驳回没有原因时接口拒绝。
- 现有数据库可升级，升级前自动备份，历史记录不丢失。

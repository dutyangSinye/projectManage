# 芯烨工时管理系统交互设计

> 版本：v2.0.27 ｜ 日期：2026-08-26 ｜ 状态：已修订，开发中

## 1. 导航重设计

工作空间导航调整为：

1. 工作台
2. 我的工时
3. 工时审批（审批人可见，显示未处理数量，内含“待我审批 / 已审批” TAB）
4. 管理报表

管理导航保留：项目管理、集成与通知、系统审计（管理员可见）。移除“提交本周期”和“飞书审批同步”作为主操作。

## 2. 核心流程

### 2.0 飞书登录

```text
飞书内打开系统 → 系统检查登录会话
    ├─ 已登录 → 加载当前用户和业务数据
    └─ 未登录 → 显示“使用飞书登录” → 飞书 H5 SDK 获取授权码 → 后端换取身份 → 建立会话
```

登录失败时不创建会话，页面保留“重新使用飞书登录”入口并显示失败原因；退出登录后清除会话并回到登录状态。正式 app 模式不展示演示身份切换器。该模式不要求配置回调 URL。

### 2.1 员工填报

```text
工作台/我的工时 → 新增工时 → 填写项目、日期、阶段、数量、工作描述
    ├─ 仅保存草稿 → DRAFT，可继续编辑
    └─ 保存并提交 → 解析实际审批人 → PENDING_APPROVAL → 飞书通知 → 详情页
```

表单主按钮固定为“保存并提交”，次按钮为“保存草稿”。提交成功页展示：单号、审批人、提交时间、通知状态和“查看详情”。

### 2.2 审批人处理

```text
飞书通知链接/待我审批 → 审批详情 → 通过
                               └─ 驳回 → 填写驳回原因 → REJECTED
```

通过不需要额外确认；驳回使用二次确认，原因最少 2 个字。处理后按钮置灰并展示处理人、处理时间、意见。

### 2.3 驳回重提

员工在我的工时看到“已驳回”和原因，进入编辑，保存并提交后回到 `PENDING_APPROVAL`。原审批意见保留在时间线中，当前审批版本单独展示。

## 4. 页面状态

所有列表和详情页保留默认、加载、空、错误、成功五态。

- 空态：明确显示没有数据，并提供下一步，例如“新增工时”或“暂无待审批”。
- 错误态：保留当前筛选条件，提供重试；通知失败不伪装成审批失败。
- 成功态：显示本地单号和状态结果；通知失败时用黄色提示，并保留“重新发送”。
- 审批详情处理中：通过/驳回按钮显示 loading，防止重复点击。
- 已处理详情：操作区变为只读，展示最终结果和意见。
- 工时项目筛选：默认只展示当前项目选择框；点击后展开下拉面板，面板顶部显示名称/编码筛选输入，输入后收窄选项；选择项目后面板自动收起，选项仅展示项目编码和名称，不展示审批人。
- 我的工时中已提交记录点击“查看”时，必须携带当前工时 ID 请求最新审批任务；没有审批任务时才显示空态，不能因未设置前端选中对象而误显示“还没有可查看的工时提交”。
- 管理报表图表：图表无数据时显示空态；所有新数据统一按“天”统计和展示，历史小时数据不作为新填报选项。
- 我的工时详情：查看已提交记录必须展示当前工时的完整字段和审批状态；通知失败时同时展示飞书返回的错误原因和“重新发送”入口（由审批人使用）。
- 飞书通知错误 `230013`：提示“当前应用未对该审批人开放，请在飞书应用后台的可用范围中加入该用户后重试”，并保留本地审批任务为待审批。
- 报表工具栏：查询按钮按当前一级部门和起止日期刷新 KPI 与图表；导出明细按钮使用完全相同的筛选条件下载 CSV。导出列包含工时单号、提交人、部门、项目、阶段、工时类型、工作状态、日期范围、工时天数、审批人、审批状态、提交时间和处理时间；仅导出 `DAY` 单位。
- 集成入口：非系统管理员不显示导航和页面；直接访问接口返回无权限。

## 6. 关键防呆

- 项目没有审批人时，表单显示“请先联系项目管理员配置审批人”，提交按钮不可用。
- 项目审批人就是当前填报人时，表单显示“本人填报将由上级领导审批”，并将上级领导作为实际审批人预览。
- 项目审批人就是当前填报人且未配置有效上级领导时，表单显示“请先配置上级领导”，提交接口返回 `APPROVER_SELF_NO_LEADER`。
- 项目管理中审批人和上级领导必须分别选择；保存成功后只影响后续新提交，已提交任务保留原实际审批人快照。
- 飞书 app 模式下所有业务请求以 Session 中的飞书用户为准，忽略 `X-Demo-User-Id`；未登录业务接口统一返回 `AUTH_REQUIRED`。
- 飞书 OAuth 登录成功后必须匹配本地已同步且启用的组织用户；无法匹配或用户已停用时拒绝进入系统。
- 项目管理页面提供“同步组织架构”；同步成功后刷新人员选择，停用或同步失败的用户不出现在新配置选项中。
- 项目管理页面默认只展示项目列表；点击“新增项目”或“编辑”后打开模态弹窗，保存、取消、点击关闭或遮罩后自动收起。
- 项目弹窗桌面端宽度受限并居中显示，移动端占满可用宽度并支持内容滚动；弹窗打开时禁止背景页面滚动。
- 项目部门使用组织架构部门下拉选择，组织同步后刷新部门选项；没有启用部门时禁止保存项目。
- 新增/编辑项目必须填写项目编码、名称、负责人和项目状态；项目编码重复时保持表单并提示错误。
- 删除项目仅标记为已删除并关闭填报；存在工时历史的项目不可物理删除，历史工时详情仍可访问。
- 项目列表默认隐藏已删除项目；接口支持按项目编码和名称查询，页面默认展示全部未删除项目。
- 提交后表单字段和保存按钮锁定，避免员工误改审批快照。
- 审批人只能看到分配给自己的待审任务；越权请求返回无权限错误。
- 驳回原因在列表、详情时间线和重新编辑页面都可见。
- 不把“周期”作为提交入口，避免用户误以为会合并多条工作内容。

## 7. v2.0.10 界面优化规则

- 品牌区统一展示“芯烨 / 工时管理系统”两级名称，桌面侧栏和登录页保持同一品牌标识。
- 页面标题、操作区和数据区使用稳定的间距层级；项目列表的“编辑”“删除”操作保持独立点击区域，避免误触。
- 桌面端侧栏、顶栏和卡片强化层级关系；按钮、输入框和状态标签统一焦点、悬停和禁用状态。
- 移动端增加底部主导航，工作台、我的工时、待审批、报表和管理入口保持可达；表单操作按钮适配单列布局。
- 项目管理和工时列表在窄屏下转为信息块展示，保留关键字段，不依赖整张宽表横向浏览。
- 工时列表在窄屏下将工作描述收进项目单元格，项目管理保留项目、状态和操作列；编辑/删除操作使用独立弹性间距。
- 保持浅色办公台风格、青绿色主色和语义状态色，卡片圆角不超过 8px，触摸目标不小于 44px。

## 8. v2.0.11 工时看板规则

- 报表页名称为“工时看板”，默认展示当月数据和“全部一级部门”。
- 一级部门按工时关联项目的所属组织部门向上追溯到根部门计算；项目未配置部门时归入“未分配部门”。
- 筛选项仅展示当前启用组织部门中实际出现在项目数据里的一级部门，并保留“全部一级部门”。
- 看板顶部展示总工时、填报人数、执行中项目、待审批记录和已通过记录；总工时只统计 `APPROVED`、`LOCKED`，待审批单独计数。
- 看板图表展示项目投入排行、人员工时分布、项目阶段工时、审批状态、工时类型和一级部门对比；所有数量按当前日期和部门筛选实时更新。
- 看板图表按现有浅色办公台风格展示：项目投入、人员分布使用横向柱状图；项目阶段和工时类型使用柱状图；审批状态使用环形图；项目阶段占比使用 100% 堆叠柱状图。全部图表保持稳定高度并响应筛选。
- 点击部门筛选后，所有 KPI 和图表同步收窄到该一级部门；“一级部门对比”在单部门模式下仍显示当前筛选结果，避免出现与 KPI 不一致的数据。
- 桌面端使用 KPI 横排和多列分析区，移动端 KPI 两列、筛选项横向滚动、分析卡片单列堆叠；部门名称过长时截断并通过完整文本属性保留可读性。
- 报表加载、空数据和接口错误均保留明确状态；刷新操作不重置当前部门和日期筛选。

## 9. v2.0.12 项目弹窗规则

- 项目列表是项目管理默认唯一主内容；新增和编辑不再在列表上方插入表单。
- 新增/编辑弹窗包含项目基础信息、组织用户、项目部门、状态和可填报设置，编辑时回填原项目数据。
- 关闭按钮、取消按钮和遮罩点击均只关闭弹窗，不提交或修改数据；保存成功后关闭弹窗并刷新列表。
- 弹窗内表单校验和接口错误保留在弹窗或全局提示区，失败时不丢失已填写内容。
- 移动端弹窗使用近全屏布局，底部操作区保持可见，输入控件触摸目标不小于 44px。

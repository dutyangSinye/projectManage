# 芯烨工时管理系统 UX 走查报告

> 版本：v2.0.30 ｜ 日期：2026-08-27 ｜ 状态：开发验证完成，等待用户 UAT

## 走查结论

- 员工首页能直接找到“新增工时”，主按钮明确为“保存并提交”。
- 周期不再作为提交入口，减少批量提交造成的审批人混用风险。
- 列表直接展示项目、工作内容、工时和审批人；驳回原因跟随记录展示。
- 审批人从“工时审批”的“待我审批” TAB 进入详情即可处理；“已审批” TAB 保留历史结果，审批快照和时间线减少核对成本。
- 通过/驳回使用明确动作文案；驳回原因在接口和页面均强制校验。
- 通知失败与审批失败分开表达，避免用户误以为工时没有提交成功。
- 项目管理明确区分“审批人”和“上级领导”；填报人就是审批人时，工时编辑页展示实际审批人，避免用户误判审批去向。
- 项目管理集中提供新增、编辑、删除和组织架构同步，人员选择不再依赖手工输入，降低离职/转岗人员被继续配置的风险。
- 项目管理默认保持列表视图，只有明确点击新增或编辑才通过弹窗进入表单；项目部门也使用组织部门选择，减少手工录入错误。
- 移动端通过底部导航保持主要入口可达；工时列表展示项目、工作描述、状态和操作，项目管理展示项目、状态和编辑/删除操作，避免横向拖动才能完成关键操作。
- 工时看板以一级部门作为第一筛选维度，默认显示全部部门；管理者可以先看全局再切换“产品研发部”等部门，减少在项目列表中逐一查找的成本。
- KPI 与图表共享同一筛选请求，部门切换后总量、待审批和分布同步更新，避免看板各区块口径不一致。
- 移动端把日期与部门筛选保持在同一横向操作带，分析卡片改为单列，长项目名以省略号处理并保留悬停完整文本。

## 建议排期

| 优先级 | 建议 | 原因 |
|---|---|---|
| P1 | 接入真实飞书 OAuth 和组织同步 | 当前演示身份切换仅用于 mock 验证 |
| P1 | 增加飞书应用精确私聊消息 | 群机器人适合 MVP，私聊更精准 |
| P2 | 支持管理员批量调整项目审批人 | 项目数量增多后降低维护成本 |
| P2 | 增加已通过工时更正单 | 满足月结后的修订需求 |

开发侧未发现必须在本版本修复的 UX 缺陷。

## v2.0.11 看板走查结论

- 首屏可直接看到当前部门、统计范围、总工时和待审批记录，核心信息层级清晰。
- 部门筛选、日期筛选和刷新看板的动作结果明确；接口错误会回到全局提示区，不会静默显示旧数据。
- 无数据部门显示解释性空态，不会出现只有空白卡片的死路。
- 移动端无整体横向滚动，筛选带的局部横向滚动可发现且不影响 KPI 和分析内容阅读。

本次未发现必须修复的 UX 缺陷；用户仍需在 NAS 环境确认真实组织架构数据下的部门名称和统计口径。

项目弹窗复测确认：移动端表单区域独立滚动，取消/保存操作区始终可见，关闭和取消不会提交数据。

## v2.0.12 弹窗走查结论

- 列表页不再被长表单推到下方，项目查询和编辑入口更容易定位。
- 弹窗提供明确的关闭、取消和保存动作，减少误操作；移动端保持表单可滚动和底部操作可达。

本次未发现必须修复的 UX 缺陷。

## v2.0.13 应用消息走查结论

- 提交后页面仍以本地审批状态为准，飞书消息只是通知结果，不会把“通知失败”误显示为“审批失败”。
- 应用消息发送失败时，审批详情保留明确的重新发送入口，用户不需要重新创建工时单。

## v2.0.14 应用卡片走查结论

- 待审批摘要和打开入口集中在同一张卡片中，审批人无需从正文中寻找裸链接。
- 入口文案明确为“打开工时系统”，与飞书内置浏览器打开行为一致；实际客户端行为待用户点击验收。

## v2.0.15 AppLink WebView 走查结论

- 使用飞书官方 AppLink 作为卡片目标，避免普通 URL 行为受客户端默认浏览器策略影响。
- 审批人仍只需点击“打开工时系统”，不会看到额外的跳转步骤；AppLink 卡片已发送，实际客户端容器待用户验收。

## v2.0.16 走查结论

- 项目筛选先输入名称/编码再选择，减少长项目列表中的查找成本；审批人信息保留在实际审批人提示中，项目选项更易扫描。
- 天和小时不再以一个无单位数字混合展示，工作台、列表和看板都保留明确单位，避免管理人员误读。
- ECharts 将项目、人员和部门投入放在同一看板内，并共享当前日期/一级部门筛选；移动端改为单列图表，信息仍可连续阅读。
- 集成与通知只对系统管理员显示，组织同步与通知健康状态集中在一个入口，普通填报用户不会看到与其无关的管理操作。

本次未发现必须修复的 UX 缺陷；待管理员在 NAS 环境完成真实组织同步和移动端最终验收。

## v2.0.20 走查结论

- 工时单位统一为天，填报人和审批人不再需要理解或切换小时口径。
- 看板 KPI、项目投入、人员分布、阶段、状态、项目×阶段占比和工时类型均共享天数口径，阅读时不会出现同一页面多个单位。
- 移动端保持浅色办公台风格，图表单列展示，日期和一级部门筛选仍可操作。

本次未发现必须修复的 UX 缺陷；NAS 已更新 v2.0.20，待用户在飞书内完成最终页面验收。

## v2.0.27 走查结论

- 用“工时审批”作为菜单名称覆盖待处理和历史结果，避免用户误以为入口只能查看待办。
- 两个 TAB 保持同一列表结构和详情入口，用户无需学习新的页面路径；已审批详情隐藏处理按钮，降低误操作风险。
- 移动端 TAB 采用整行可点击区域并保留数量徽标，待处理和历史结果在窄屏下仍易于切换。

本次未发现必须修复的 UX 缺陷。

线上发布验收通过：服务启动完成后页面资源、飞书登录配置和审批认证门禁均正常，未发现影响用户进入“工时审批”或切换 TAB 的问题。

## v2.0.25 工时列表与提交结果走查

- 我的工时先展示记录数量和审批通过天数，再展示状态筛选，用户可以先判断整体情况再定位记录。
- 项目与工作内容合并为一列，减少横向扫描；操作文案改为“查看详情”，与实际结果页一致。
- 提交结果页将单号、状态和审批人放在首屏摘要，避免用户进入页面后在长详情中寻找提交结果。
- 审批时间线独立成区，通知状态与审批状态分开表达；时间戳使用短格式，降低移动端阅读负担。
- `390×844` 走查未发现横向溢出、内容重叠或不可点击操作；本次未发现必须修复的 UX 缺陷。

# v2.0.46 报表加载故障修复

## 问题

部分项目没有配置成本预算时，工时看板会返回 `cost_usage_rate: null`。旧的 `ReportView` 响应模型只允许字符串、数字，不允许 `null`，FastAPI 因响应校验失败返回 HTTP 500。前端初始化使用单个 `Promise.all`，因此报表失败会连带阻止项目列表、工时列表等数据赋值，页面表现为持续加载或项目为空。

## 修复

- 报表 breakdown 明细字段允许 `null`，准确表达“未配置成本预算”。
- 前端先加载用户、组织、项目、工时、审批和配置等核心数据。
- 报表与集成状态改为独立容错加载，单个接口异常只提示对应模块，不阻断核心页面。
- 增加报表 schema 回归测试，覆盖未配置项目成本预算的场景。

## 验证

- 后端 `compileall` 通过。
- 前端 `pnpm run build` 通过。
- 回归测试验证 `cost_usage_rate = null` 可正常解析。
- 发布后检查 `/health`、项目接口和工时看板接口，并查看后端日志无新的响应校验异常。

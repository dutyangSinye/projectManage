# 综合项目管理系统最新需求说明

> 版本：v3.0.45  
> 日期：2026-09-07  
> 状态：当前需求基线，已实现内容与后续优化分开标注  
> 适用范围：工作台、工时管理、项目管理、系统管理

## 1. 文档目的

本文档是当前系统的统一需求基线，用于替代分散在历史 PRD、项目经营分析设计和合同附件变更说明中的重复描述。它回答三个问题：系统服务谁、每个模块要解决什么问题、哪些规则必须保持一致。

当前系统定位为项目经营管理台账，不替代财务总账、银行系统、发票系统或飞书审批本身。系统负责项目、工时、合同、收付款、预算、成本、提醒和审计之间的关联；合同收付款审批通过只代表业务确认，不直接发起银行转账。

项目费用与动态审批的详细业务口径见 `41-project-expense-workflow-design-v3.0.44.md`，生产实施与验收结果见 `42-project-expense-workflow-implementation-v3.0.45.md`。

### 2.2 本版本明确不做

- 不接入银行系统，不执行自动转账。
- 不替代会计总账，不生成会计凭证。
- 不包含发票、税务、采购、库存、工资和报销管理。
- 暂不支持多币种、汇率损益和人员成本生效日期。
- 不把飞书审批作为工时和收付款的唯一业务数据库；业务状态以本系统记录为准。
- 不依赖业务回调才能查看数据；系统支持用户主动进入和查询，飞书消息作为提醒入口。

## 5. 核心需求

### 5.1 工作台

工作台按用户角色显示上下两块内容，不让员工看到无关的经营管理区域。

#### 项目负责人区

显示负责项目数量、正常/预警/超预算项目数量、预算执行情况、已发生成本、待审批工时、应收应付和资金提醒。研发、课题、观摩项目重点显示人天、人员成本、支出合同和成本预算；实施项目同时显示收入合同、支出合同、已收、应收、已付、应付和毛利。

项目负责人可以直接发起：发起合同付款、增加收款、填报工时、处理工时审批。入口必须根据权限和项目类型动态显示。

#### 员工区

显示本月已审批工时、待审批条数、驳回待修改条数、草稿条数、最近工时和审批时间线，并提供“填报工时”主入口。最近工时点击后必须进入对应工时详情，而不是只进入工时列表。

### 5.2 工时管理

#### 我的工时

- 填报单位为“天”，不展示或计算小时。
- 同一个人同一天只能填报一次，不区分项目；不同项目也不能在同一天重复填报。
- 开始日期和结束日期必须属于同一个自然月，区间不能跨月。
- 保存草稿后可修改；提交后进入单独审批流程。
- 查看已提交工时必须展示完整信息、审批人、上级领导、审批状态、审批意见和时间线。
- 审批状态支持局部刷新和定时刷新，避免审批完成后长时间显示旧状态。

#### 工时审批

- 分为“待我审批”和“已审批”两个 TAB。
- 每一条工时单独审批，不能因为多人审批而合并成一个批次。
- 审批人等于填报人时，自动改由项目配置的上级领导审批。
- 审批通过后计入项目已发生人天和人员成本；驳回不计入。
- 审批通过和驳回都通过飞书应用消息通知相关人员。

#### 工时看板与台账

工时看板只展示工时相关指标：工时总量、填报人数、项目数、待审批数量、审批通过率、部门/人员/项目分布和时间趋势。预算、成本、收付款和毛利只在项目看板展示。

工时台账用于授权管理员查看全部日志，支持日期、层级部门、人员、项目和状态筛选，支持分页、修改允许修改的数据和删除允许删除的数据。明细导出支持按部门和自定义时间范围导出。

### 5.3 项目管理

#### 项目主信息

项目管理首页只保留以下主字段并平铺展示，避免横向滚动：项目名称、项目编号、项目状态、项目类型、项目负责人、所属部门、客户、工时填报是否允许及操作。

项目支持新增、查看、编辑、删除、分页。筛选项包括项目类型、项目部门、项目负责人和项目名称模糊查询。部门选择必须体现树形层级；选择上级部门时包含子部门，选择子部门时只匹配该子部门及其下级部门。

新增和编辑使用弹窗；项目详情页用于查看完整信息和经营结果。项目字段顺序为：项目状态、项目负责人、审批人、执行状态、上级领导，其后是项目基本信息和预算信息。

#### 动态配置

项目类型由基础配置维护，初始类型为：研发项目、课题项目、实施项目、观摩项目。类型停用后不能用于新项目，但历史数据保留原名称；已经被业务数据引用的类型不做物理删除，避免历史记录失去含义。

项目类型决定合同能力：实施项目支持收入合同和支出合同；研发、课题、观摩项目默认支持支出合同，收入侧是否开放由类型能力配置决定。

#### 预算与发生数据

项目可维护人天预算、成本预算、费用预算和项目成本预算说明。已发生人天、已发生人员成本、已发生合同成本、已发生费用成本、预算剩余和预算使用率均为系统只读计算结果。

### 5.4 合同与阶段

- 合同管理分为收入合同和支出合同两个 TAB。
- 实施项目可以同时创建收入合同和支出合同。
- 合同核心字段包括合同编号、名称、项目、客户或供应商、合同金额、签订日期、履约期间、状态、说明和附件。
- 每份合同可以配置多个收款或付款阶段，阶段包含名称、顺序、计划金额、计划日期、提前提醒天数和状态。
- 阶段已收/已付、未收/未付、结算率和单据数全部由已确认合同收付款单计算，不能手工维护。
- 合同名称进入合同详情；点击“阶段”只进入阶段列表；点击“新增阶段”才打开新增弹窗。
- 合同详情直接展示合同信息和阶段信息，附件放在合同详情页面最底部。
- 已产生收付款的阶段不可直接删除或把计划金额调低到已确认金额以下。

### 5.5 收款与付款

#### 合同收款单

合同收款单必须关联项目、收入合同和具体收款阶段，填写收款日期、金额、付款方姓名、付款方银行、付款方账号、公司收款账户、银行流水号和凭证。缺少收款方姓名、开户行或账号时不能提交。

合同收款单由出纳角色审批。审批通过后计入项目收入、增加已收、核减阶段应收，并通知申请人。

#### 合同付款单

合同付款单必须关联项目、支出合同和具体付款阶段，填写付款日期、金额、收款方姓名、收款方银行、收款方账号、公司付款账户、银行流水号和凭证。选择供应商后可以自动带出账户信息，但允许在当前单据中修改；单据保存时保留账户快照，不反向修改供应商资料。

合同付款单由出纳角色审批。审批通过后计入项目合同成本、增加已付、核减阶段应付，并通知申请人。合同收款单和合同付款单审批详情必须可以像工时审批一样点击打开完整单据。

### 5.6 项目看板和项目详情

项目看板允许项目负责人筛选自己负责的项目；拥有全部项目权限的人员可以筛选全部项目。展示收入、人员成本、合同成本、总成本、应收、应付、已收、已付、毛利、毛利率、预算执行和预警。

项目详情需要支持单项目经营分析：成本组成、人员成本使用率、合同阶段收付款分析、结项前后资金、待审批金额和风险事项。所有数字能够下钻到合同、阶段、合同收付款单或工时明细。

### 5.7 客户、供应商和人员成本

客户和供应商维护核心信息：名称、简称、统一社会信用代码、营业执照、地址、联系人、电话、邮箱、开票信息、银行账户、状态和备注。客户或供应商名称修改后，列表和项目/合同选择项应动态读取最新名称；历史单据保留当时的名称和账户快照。

人员成本作为系统管理下的独立功能，采用紧凑列表、部门/人员筛选和分页维护单天成本。暂不加入成本生效日期；工时审批通过时记录用于本次计算的人员成本快照。

### 5.8 系统管理

#### 集成与通知

维护飞书连接状态、组织同步、应用消息配置和通知记录。系统通过飞书应用消息通知工时审批、合同收付款审批结果、合同阶段到期/逾期、预算接近或超支、人天接近或超支、待审批合同收款和待审批合同付款。

飞书卡片按钮使用系统内地址并优先通过飞书内置浏览器打开。通知失败不能回滚业务状态，必须保存失败原因并支持重试。

#### 管理员管理

管理员管理用于选择哪些人员可以看到和操作哪些管理模块。未加入管理权限的人员不显示在管理员列表。权限至少覆盖项目、合同、收付款、项目看板、工时台账、人员成本、客户、供应商、出纳审批、集成与通知、基础配置和管理员管理。

#### 基础配置

动态维护项目类型、项目状态、执行状态、工时类型、合同分类、收付款方式、提醒提前天数、银行账户和客户/供应商状态。会影响数据库和流程的固定状态只能修改显示名称，不能任意新增或删除。

## 6. 统一业务口径

| 指标 | 规则 |
|---|---|
| 已发生人天 | 已审批工时天数合计 |
| 人员成本 | 已审批工时天数 × 审批通过时的人员单天成本快照 |
| 人员成本预算基线 | 人天预算 × 已审批工时加权平均单天成本 |
| 人员成本使用率 | 已发生人员成本 ÷ 人员成本预算基线 × 100% |
| 已发生合同成本 | 已审批且未冲销的合同付款单合计 |
| 总成本 | 人员成本 + 合同成本 |
| 已收 | 已审批且未冲销的合同收款单合计 |
| 已付 | 已审批且未冲销的合同付款单合计 |
| 应收 | 已到期收入阶段剩余金额合计 |
| 应付 | 已到期支出阶段剩余金额合计 |
| 收入 | 当前版本按已收确认项目收入 |
| 毛利 | 已收 - 总成本 |
| 成本预算剩余 | 成本预算 - 总成本，可显示负数用于提示超支 |
| 人天预算剩余 | 人天预算 - 已发生人天，可显示负数用于提示超支 |

加权平均单天成本：

```text
Σ（已审批工时天数 × 审批时人员单天成本） ÷ Σ（已审批工时天数）
```

预算为 0 或没有已审批工时时，人员成本使用率显示“暂无基准”，不伪造 0%。所有金额使用人民币元和两位小数，前端不能用浮点累加代替后端汇总。

## 7. 提醒与飞书通知

### 页面提醒

- 工作台项目提醒列表展示今天至未来 30 天内到期的阶段，以及已逾期阶段，最多显示 6 条。
- “未来 7 天”只用于统计口径，不限制提醒列表展示范围。
- 项目详情显示阶段逾期、临期、结项前未收/未付、无计划日期、预算接近/超支和待审批收付款。

### 飞书提醒

| 类型 | 触发条件 | 通知对象 |
|---|---|---|
| 工时待审批 | 工时提交后产生待审批任务 | 实际审批人 |
| 工时审批结果 | 工时通过或驳回 | 填报人 |
| 合同阶段到期/逾期 | 进入提前提醒窗口、当天到期或逾期 | 项目负责人 |
| 成本预算接近/超支 | 使用率达到 80% 或 100% | 项目负责人 |
| 人天预算接近/超支 | 使用率达到 80% 或超过 100% | 项目负责人 |
| 待审批合同收款 | 存在待出纳审批合同收款单 | 所有启用且具备出纳审批权限的用户 |
| 待审批合同付款 | 存在待出纳审批合同付款单 | 所有启用且具备出纳审批权限的用户 |
| 合同收付款审批结果 | 合同收款单或合同付款单审批通过/驳回 | 申请人 |

同一项目、同一阶段或同一单据在同一业务日、同一提醒类型只发送一次；失败消息保留记录并允许后续重试。

## 8. 非功能要求

- 桌面端信息密度高但不出现无意义横向滚动；项目管理首页信息完整平铺。
- 移动端采用单列布局，按钮可点击区域和弹窗适配 390×844 视口。
- 所有弹窗点击遮罩不应误关闭正在填写的新增/编辑/审批单据，必须使用明确关闭按钮或取消操作。
- 列表加载、空数据、错误、成功和权限不足均有明确状态。
- 所有关键业务动作写入审计日志。
- 业务接口统一返回可读错误，不直接展示 `[object Object]`。
- 附件上传前后都要校验类型、大小和权限；原文件不可执行宏或脚本。

## 9. 验收标准

1. 四大模块按权限显示，未授权菜单和接口均不可用。
2. 工时可以按单条提交和审批，同一人同一天不能重复填报，日期不能跨月。
3. 工时、合同、阶段、收付款和项目经营数字可以相互下钻并保持一致。
4. 实施项目同时支持收入合同和支出合同；研发类项目不会错误隐藏支出合同。
5. 已审批收付款才计入已收、已付、应收/应付核销、成本和毛利。
6. 应收和应付只统计已到期阶段的剩余金额。
7. 人员成本、合同成本、总成本和预算剩余计算正确，预算为 0 时不产生错误百分比。
8. Word、Excel、PPT、PDF 和图片附件按权限上传、预览和下载；预览失败仍可下载原文件。
9. 到期、逾期、预算、人天和待审批提醒在页面及飞书通知中按规则生成且不重复发送。
10. 桌面端和移动端页面无明显错位、遮挡和横向溢出。

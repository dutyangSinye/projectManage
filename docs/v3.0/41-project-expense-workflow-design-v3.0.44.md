# 项目费用与动态审批工作流设计

- 版本：v3.0.44
- 日期：2026-09-06
- 状态：方案已确认，高保真原型已完成；生产开发见 v3.0.45 实施说明
- 对应生产版本：v3.0.43
- 适用系统：综合项目管理系统

## 1. 结论

本功能不把审批流程或具体人员写死在代码中，也不引入复杂 BPMN 引擎。系统采用“预置流程模板 + 动态审批岗位 + 发布版本 + 单据审批快照”的轻量工作流：

- 差旅费用使用预置模板：申请人提交 → 项目审批人 → 上级领导 → 会计 → 总经理 → 出纳。
- 合同付款单、其他费用、无合同发票费用使用预置模板：申请人提交 → 项目审批人 → 经营审批 → 上级领导 → 经营副总 → 会计 → 总经理 → 出纳。
- 项目审批人从项目配置读取，上级领导从飞书组织架构读取，经营、经营副总、会计、总经理、出纳从系统“审批岗位”读取。
- 系统 RBAC 角色负责“能看什么、能做什么”；审批岗位负责“业务流转给谁”，两者分别配置。
- 单据提交时解析并固化流程版本、节点顺序和实际审批人。之后修改模板或岗位人员，不影响运行中的单据。
- 飞书只负责通知和打开系统详情，审批动作仍在系统中完成。
- 费用审批通过确认项目成本；出纳完成支付后确认已付。成本和资金只各记一次。

## 2. 背景与目标

### 2.1 背景

当前项目成本只包括已审批工时形成的人员成本，以及合同付款形成的合同成本。差旅、无合同发票和其他项目费用无法独立归集，也缺少符合公司现行制度的多级审批、支付确认和飞书通知。

### 2.2 目标

1. 将差旅、无合同发票和其他费用纳入项目成本并可追溯到原始单据。
2. 支持两套公司常用审批链，同时允许管理员调整岗位、节点和审批方式。
3. 将费用确认与实际支付分开，准确展示项目成本、应付和已付。
4. 每一步审批、驳回、撤回、自动通过、支付和冲销均保留审计记录。
5. 提交前发现审批人缺失，避免单据进入无人处理状态。

### 2.3 非目标

- 不替代财务总账，不生成会计凭证，不直接连接银行转账。
- 不做发票查验、税额抵扣、借款核销、预算占用会计或完整报销平台。
- 不提供任意拖拽、条件网关、并行子流程等完整 BPMN 能力。
- 首期不处理人员成本生效日期和多币种。

## 3. 业务对象与边界

| 对象 | 用途 | 是否计入项目成本 | 是否影响已付 |
| --- | --- | --- | --- |
| 人员工时成本 | 工时审批通过后按成本快照生成 | 是 | 否 |
| 合同付款 | 支出合同阶段付款确认 | 是 | 是 |
| 差旅费用 | 员工因项目发生的交通、住宿等费用 | 审批通过后计入 | 出纳支付后增加 |
| 无合同发票费用 | 无支出合同但有发票的项目支出 | 审批通过后计入 | 出纳支付后增加 |
| 其他费用 | 不属于以上类型的项目支出 | 审批通过后计入 | 出纳支付后增加 |
| 冲销 | 更正已确认成本或资金记录 | 反向冲减 | 按冲销对象处理 |

费用单是成本事实来源，费用支付是资金事实来源。已审批费用不得再通过“合同付款”重复计入项目成本。

## 4. 费用单设计

### 4.1 通用字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 费用单号 | 自动 | `FY-年月日-流水号`，全局唯一 |
| 费用类型 | 是 | 差旅费用、无合同发票费用、其他费用 |
| 项目 | 是 | 只能选择当前用户有发起权限且启用费用填报的项目 |
| 申请人 | 自动 | 当前登录飞书用户，不允许代填；代填作为后续扩展 |
| 申请部门 | 自动 | 保存提交时的飞书部门快照 |
| 费用发生日期 | 是 | 不得晚于提交日期；管理员可通过配置允许补录天数 |
| 申请金额 | 是 | 大于 0，人民币，两位小数 |
| 计入项目成本金额 | 是 | 默认等于申请金额，可由有权限人员调整，必须大于 0 |
| 是否需要支付 | 是 | 默认“是”；已由公司账户支付等场景可设为“否” |
| 收款方名称 | 需要支付时 | 支付对象的姓名或单位名称 |
| 收款银行/账号 | 需要支付时 | 保存快照；列表默认脱敏，只在授权场景显示完整值 |
| 费用说明 | 是 | 描述费用原因和项目关联，10 至 500 字 |
| 附件 | 是 | 至少一项报销凭证、发票或审批依据；新建时即可预选上传 |
| 备注 | 否 | 补充说明 |

### 4.2 差旅费用字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 出差开始/结束日期 | 是 | 结束日期不得早于开始日期 |
| 出发地/目的地 | 是 | 文本或基础配置选项 |
| 出差事由 | 是 | 与项目工作内容对应 |
| 同行人员 | 否 | 从飞书组织人员中多选，仅作记录，不自动生成其费用单 |
| 交通费 | 是 | 可为 0 |
| 住宿费 | 是 | 可为 0 |
| 餐费/补贴 | 是 | 可为 0 |
| 其他差旅费 | 是 | 可为 0，非 0 时必须说明 |

差旅申请金额由费用明细合计自动计算，不能直接手工覆盖。首期不对接公司已有的飞书差旅审批，避免两个审批实例互相冲突。

### 4.3 无合同发票费用字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 供应商 | 否 | 可从供应商库选择；选择后带出名称和账户，可修改为单据快照 |
| 发票类型 | 是 | 从基础配置读取 |
| 发票代码 | 视票种 | 与发票号码组合去重 |
| 发票号码 | 是 | 同一供应商、发票代码、发票号码不得重复使用 |
| 开票日期 | 是 | 不得晚于当前日期 |
| 发票含税金额 | 是 | 大于 0，人民币，两位小数 |
| 计入项目成本金额 | 是 | 默认等于含税金额，调整时必须填写原因 |
| 付款到期日 | 需要支付时 | 用于应付和逾期提醒 |

发票附件必须包含至少一个 PDF 或图片。Office 文件可以作为补充附件，但不能代替发票凭证。

### 4.4 其他费用字段

- 费用类别从基础配置动态读取，例如招待费、材料费、服务费、办公费。
- 供应商可选；需要付款时必须填写收款方和账户。
- 非 0 的计入项目成本金额必须有费用说明和附件。

## 5. 状态机与金额确认

```text
DRAFT 草稿
  └─提交→ PENDING_APPROVAL 审批中
             ├─驳回→ REJECTED 已驳回
             ├─撤回→ WITHDRAWN 已撤回
             └─全部业务审批通过→
                  ├─无需支付→ APPROVED 已审批
                  └─需要支付→ APPROVED_PENDING_PAYMENT 待支付
                                      └─出纳确认支付→ PAID 已支付

APPROVED / APPROVED_PENDING_PAYMENT / PAID
  └─授权冲销→ REVERSED 已冲销
```

状态规则：

- 草稿和驳回单允许申请人修改；审批中的单据只读。
- 至少一个节点已处理后仍允许申请人撤回，但必须记录原因；进入出纳支付确认后不允许撤回。
- 驳回默认退回申请人。申请人修改并重新提交时，创建新的审批实例版本，旧实例完整保留。
- 业务审批全部通过时生成费用成本流水。出纳支付不再生成成本流水，只生成资金流水。
- 已审批或已支付单据不能直接修改；错误数据通过冲销处理。

### 5.1 项目经营口径

```text
项目总成本
= 人员成本
+ 合同成本
+ 差旅成本
+ 无合同发票成本
+ 其他成本
- 成本冲销

项目费用应付
= 已审批且需要支付的费用金额
- 已支付费用金额
- 支付冲销金额

项目已付
= 已确认合同付款
+ 已确认费用支付
- 已付冲销
```

预算执行率使用“项目总成本 / 项目成本预算”。费用审批通过后立即影响成本预算预警，不等待出纳支付。

## 6. 轻量工作流模型

### 6.1 为什么不写死

审批链中的组织和人员会变化。写死姓名或顺序会导致调岗、请假、岗位调整时必须发版，也无法解释历史单据当时为什么流转给某个人。

### 6.2 为什么暂不使用完整 BPMN

当前只有少量固定顺序的串行审批，核心变量是“节点由谁处理”。引入完整 BPMN 会增加流程建模、运行时、迁移、可视化和运维成本。轻量模板足以覆盖当前流程，同时保留后续扩展条件节点和并行节点的数据结构。

### 6.3 核心对象

| 对象 | 含义 |
| --- | --- |
| 审批岗位 | 业务岗位，例如会计、出纳、经营审批、经营副总、总经理 |
| 流程定义 | 适用于某类单据的模板，例如“差旅费用审批” |
| 流程版本 | 已发布模板的不可变版本 |
| 流程节点 | 节点顺序、审批人来源、或签/会签、是否允许跳过 |
| 流程实例 | 某张单据提交后生成的一次运行实例 |
| 审批任务 | 分配给实际审批人的待办 |
| 操作日志 | 提交、通过、驳回、撤回、自动通过、转交、支付和冲销记录 |

### 6.4 审批人来源

| 解析方式 | 数据来源 | 失败处理 |
| --- | --- | --- |
| `PROJECT_APPROVER` | 单据项目的审批人配置 | 阻止提交并提示项目缺少审批人 |
| `DIRECT_MANAGER` | 申请人的飞书直属上级 | 阻止提交并提示组织架构缺少直属上级 |
| `APPROVAL_POSITION` | 系统审批岗位的有效成员 | 阻止提交并指出缺失岗位 |
| `SPECIFIED_USER` | 模板中指定的飞书用户 | 仅用于特殊临时流程，不作为默认设计 |

### 6.5 审批方式

- 单人：解析为一人，由该人处理。
- 或签 `ANY`：岗位内所有成员收到待办和飞书通知，任意一人处理后节点完成，其他任务关闭。
- 会签 `ALL`：岗位内所有成员均需通过；任一人驳回则节点驳回。
- 当前预置的经营、会计、总经理和出纳岗位默认使用或签。
- 出纳节点是支付确认节点，除审批意见外必须填写实际支付日期、金额、付款账户和凭证。

### 6.6 自审与重复审批人

1. 项目审批人等于申请人时，项目审批节点改由申请人的飞书直属上级处理。
2. 直属上级仍等于申请人或无法解析时，阻止提交，不允许静默跳过。
3. 相邻两个普通审批节点解析为同一人时，后一节点自动通过，并记录“因前一节点已由同一审批人通过而自动通过”。
4. 非相邻节点保持独立审批，避免经营、财务等不同职责被无意合并。
5. 出纳支付节点永不自动通过，即使处理人与前一节点相同，也必须填写实际支付信息。

### 6.7 提交前预检与快照

提交前展示“审批路径预览”：

```text
项目审批人：张三
经营审批：李四 / 王五（任一人审批）
上级领导：赵六
经营副总：钱七
会计：孙八
总经理：周九
出纳：A / B（任一人确认支付）
```

所有节点均解析成功后才能提交。提交事务内保存流程版本、人员 ID、人员姓名、部门、岗位、顺序和审批方式快照。流程模板或飞书组织变化只影响后续新提交单据。

## 7. 预置流程模板

### 7.1 差旅费用审批

| 顺序 | 节点 | 审批人来源 | 默认方式 | 节点职责 |
| ---: | --- | --- | --- | --- |
| 1 | 项目审批 | 项目审批人 | 单人 | 确认项目相关性和必要性 |
| 2 | 上级领导 | 飞书直属上级 | 单人 | 确认人员行为和费用合理性 |
| 3 | 会计审核 | 会计岗位 | 或签 | 核对票据、金额和成本归属 |
| 4 | 总经理审批 | 总经理岗位 | 或签 | 最终经营审批 |
| 5 | 出纳支付 | 出纳岗位 | 或签 | 核对收款账户并登记实际支付 |

### 7.2 合同付款单、其他费用、无合同发票费用审批

| 顺序 | 节点 | 审批人来源 | 默认方式 | 节点职责 |
| ---: | --- | --- | --- | --- |
| 1 | 项目审批 | 项目审批人 | 单人 | 确认项目归属、合同或费用真实性 |
| 2 | 经营审批 | 经营审批岗位 | 或签 | 核对项目经营合理性 |
| 3 | 上级领导 | 飞书直属上级 | 单人 | 确认申请人事项 |
| 4 | 经营副总 | 经营副总岗位 | 或签 | 经营条线复核 |
| 5 | 会计审核 | 会计岗位 | 或签 | 核对金额、票据、预算和科目 |
| 6 | 总经理审批 | 总经理岗位 | 或签 | 最终审批 |
| 7 | 出纳支付 | 出纳岗位 | 或签 | 核对账户并登记实际支付 |

现有“合同付款单”迁移到第二套模板。现有“合同收款单”仍使用出纳确认流程，不因本次费用流程强制增加多级审批；后续如需扩展，可单独发布收款流程模板。

## 8. 流程配置与发布

### 8.1 审批岗位页面

路径：系统管理 → 审批配置 → 审批岗位。

列表只显示已配置岗位，不显示未加入的人员。岗位卡片展示岗位名称、有效人数、最近修改时间和状态。点击编辑弹窗从飞书组织树选择人员，支持按部门和姓名筛选。

系统预置岗位编码：

- `OPERATIONS_REVIEWER`：经营审批。
- `OPERATIONS_VP`：经营副总。
- `ACCOUNTANT`：会计。
- `GENERAL_MANAGER`：总经理。
- `CASHIER`：出纳。

编码不可修改或删除，显示名称和人员可以调整。至少一条已生效流程引用的岗位不得停用为空。

### 8.2 审批流程页面

路径：系统管理 → 审批配置 → 审批流程。

- 列表展示适用单据、当前发布版本、节点数、状态和最近发布人。
- 点击流程名称进入版本详情，默认只读。
- 点击“新建版本”复制当前版本，在草稿中调整节点顺序、岗位、审批方式和通知开关。
- 发布前执行人员解析演练：选择一个项目和申请人，展示实际审批路径及错误。
- 已发布版本不可编辑，只能复制为新版本；停用模板只阻止新单据提交，不影响运行实例。

```text
│ 拖放/选择文件  费用说明  备注                    │
└────────────────────────────────────────────────┘
审批路径预览：项目审批人 → …… → 出纳
                         [取消] [保存草稿] [提交审批]
```

- 附件在单据保存前进入前端暂存区，保存实体成功后自动关联上传，沿用合同附件模式。
- 切换费用类型时先提示将清空该类型专属字段，防止表单残留。
- 提交前同时校验字段、重复发票、项目预算和审批路径。
- 接近或超过成本预算只提示并标红；是否禁止超预算由基础配置控制。

### 9.4 费用详情与审批

详情顶部展示状态、费用类型、项目、申请人、成本金额和待支付金额。正文分为：基本信息、费用明细、支付信息、附件、审批时间线、成本/资金流水。

审批人通过飞书卡片进入具体费用详情。页面底部固定操作栏展示“通过、驳回”；驳回意见必填。出纳节点改为“确认支付”，弹窗必填实际支付日期、支付金额、公司付款账户和支付凭证。

审批前二次确认内容必须包含项目、费用类型、成本金额、支付金额、收款方和当前节点职责。

### 9.5 项目详情与项目看板

项目详情新增“费用明细”子页签，展示各费用类型金额、待支付、已支付和明细。概况及项目看板的成本组成扩展为：

- 人员成本。
- 合同成本。
- 差旅成本。
- 无合同发票成本。
- 其他成本。

图表点击后下钻到项目费用列表，并继承项目、类型和日期筛选。项目总成本、预算剩余、预算执行率和毛利统一使用新成本口径。

## 10. 权限与数据范围

审批岗位不授予菜单权限。用户即使属于“会计岗位”，仍需通过 RBAC 获得相应菜单 `VIEW`/`APPROVE` 权限；但已分配给本人的审批任务允许查看该单据必要详情。

新增资源与操作：

| 资源 | 操作 |
| --- | --- |
| 项目费用 | `VIEW / CREATE / EDIT / DELETE / APPROVE / EXPORT / REVERSE` |
| 审批岗位 | `VIEW / CONFIGURE` |
| 审批流程 | `VIEW / CREATE / EDIT / PUBLISH / DISABLE` |
| 费用支付 | `VIEW / APPROVE / REVERSE` |

数据范围沿用 `SELF / OWNED_PROJECTS / DEPARTMENT_AND_CHILDREN / ALL`。审批待办按任务授权，不受项目列表范围阻断；审批完成后继续查看详情时，至少保留该审批实例的只读访问权。

敏感字段规则：银行账号默认只显示后四位；申请人编辑、会计审核、出纳支付和有财务敏感字段权限的人员可查看完整值。导出沿用同一脱敏和数据范围规则。

## 11. 飞书通知与提醒

### 11.1 即时通知

| 事件 | 接收人 | 卡片动作 |
| --- | --- | --- |
| 新审批节点开始 | 当前节点全部候选人 | 打开对应单据审批详情 |
| 或签被其中一人处理 | 其他候选人 | 待办关闭，不重复提醒 |
| 单据驳回 | 申请人、项目负责人 | 打开单据详情 |
| 业务审批完成待支付 | 出纳岗位成员、申请人 | 出纳进入支付确认，申请人查看进度 |
| 支付完成 | 申请人、项目负责人 | 打开已支付详情 |
| 单据冲销 | 申请人、项目负责人、相关财务岗位 | 打开冲销记录 |

飞书卡片标题统一使用“综合项目管理系统”，AppLink 携带费用单 ID 和审批任务 ID，优先在飞书内置浏览器打开。

### 11.2 预警

- 审批节点超过配置时长未处理，按策略提醒当前审批人。
- 费用已审批但超过付款到期日未支付，提醒出纳、申请人和项目负责人。
- 费用使项目成本预算接近或超支，提醒项目负责人及配置的经营岗位。
- 通知发送失败进入现有通知中心，可查看原因并重试。

通知幂等键包含事件类型、单据 ID、审批实例版本、节点 ID 和提醒日期，避免重复发送。

## 12. 数据模型

### 12.1 业务表

| 表 | 关键字段 |
| --- | --- |
| `project_expenses` | 单号、类型、项目、申请人/部门快照、金额、成本金额、支付标记、状态、当前流程实例、版本号 |
| `project_expense_items` | 费用单、明细类型、说明、金额、发生日期、扩展 JSON |
| `project_expense_invoices` | 费用单、供应商快照、票种、发票代码、发票号码、开票日期、含税金额 |
| `project_expense_payments` | 费用单、实际支付金额/日期、付款账户、收款方账户快照、出纳、状态 |
| `entity_attachments` | 复用统一附件表，以实体类型和实体 ID 关联费用及支付凭证 |

发票去重索引建议为 `supplier_id + normalized_invoice_code + normalized_invoice_number`。没有供应商 ID 时使用收款方规范化名称参与去重，并允许有权限人员提交重复例外原因。

### 12.2 工作流表

| 表 | 关键字段 |
| --- | --- |
| `approval_positions` | 岗位编码、名称、状态、说明 |
| `approval_position_users` | 岗位、飞书用户、有效状态 |
| `workflow_definitions` | 流程编码、名称、适用单据类型、当前发布版本、状态 |
| `workflow_versions` | 流程、版本号、草稿/已发布/停用、发布人和发布时间 |
| `workflow_nodes` | 版本、顺序、节点编码、审批人解析器、岗位、审批方式、配置 JSON |
| `workflow_instances` | 单据类型/ID、流程版本、申请人、状态、当前节点、提交快照 |
| `workflow_tasks` | 实例、节点、候选审批人、状态、意见、处理时间、是否自动处理 |
| `workflow_action_logs` | 操作类型、操作人、前后状态、意见、时间、扩展信息 |

所有外键使用 ID，姓名、部门、岗位名称等同时保存展示快照。金额使用定点小数，不使用浮点数。

### 12.3 项目流水扩展

`project_ledger_entries.entry_type` 增加：

- `TRAVEL_COST`
- `NON_CONTRACT_INVOICE_COST`
- `OTHER_COST`
- `EXPENSE_PAYMENT`
- `REVERSAL`

成本与资金建议通过 `ledger_dimension = COST / CASH` 或等价字段区分。每条流水使用唯一 `idempotency_key`，示例：`expense-cost:{expense_id}:{approval_version}`、`expense-payment:{payment_id}`。

## 13. 核心事务与并发

### 13.1 提交

一个数据库事务内完成：校验单据版本 → 解析审批人 → 创建流程实例 → 创建首节点任务 → 更新单据状态。事务提交后异步发送飞书通知。

### 13.2 审批

使用单据版本号和任务状态做乐观锁。重复点击同一审批动作返回已有结果；或签首人处理后原子关闭同节点其他任务。

### 13.3 成本确认

最后一个业务审批节点通过时，在同一事务内更新单据状态并写入唯一成本流水。事务失败则两者都不落库。

### 13.4 支付确认

出纳提交时复核待支付余额，写入费用支付记录和资金流水，再把单据更新为已支付或部分支付。首期默认一次全额支付；数据模型保留多次支付能力，页面首期不开放拆分支付。

## 15. 验收标准

### 15.1 功能

- 三类费用均可保存草稿、预选附件、提交、审批、驳回、撤回、重提、支付和冲销。
- 两套预置流程按设计顺序运行，运行实例不受后续模板修改影响。
- 项目审批人、上级领导和五类审批岗位均能正确解析。
- 或签任一人处理后关闭同节点其他待办；会签需全部通过。
- 自审转上级、相邻重复审批人自动通过、出纳不自动通过规则正确。
- 审批通过只生成一次成本，支付只生成一次资金记录。
- 项目详情和项目看板能按费用类型下钻并与流水逐笔对账。

### 15.2 权限和安全

- 无菜单权限看不到入口，直接调用接口返回 403。
- 审批人仅能处理分配给自己的有效任务。
- 部门数据范围包含所有下级部门。
- 银行账号、附件、导出和审批详情遵循字段权限与数据范围。
- 已审批单据不可直接修改，全部关键动作写入审计日志。

### 15.3 通知

- 每个新节点的所有候选人收到一张飞书卡片，链接直达对应审批详情。
- 审批结果、待支付、支付完成、驳回和冲销通知接收人正确。
- 通知失败不回滚业务事务，可在通知中心看到并重试。

### 15.4 回归

- 现有工时、合同、合同付款、收款、看板、RBAC、飞书登录和附件功能保持正常。
- 既有合同付款仍只计一次合同成本，不与费用成本重复。
- 当前项目总成本升级后，历史项目数字在没有新费用时保持一致。

## 16. 实施顺序与工作量

| 阶段 | 内容 | 单人估算 |
| --- | --- | ---: |
| 1 | 高保真原型、字段和口径确认 | 2-3 天 |
| 2 | 工作流、审批岗位、状态机和迁移脚本 | 3-4 天 |
| 3 | 项目费用、发票、附件和费用支付后端 | 3-4 天 |
| 4 | 费用列表、新增、详情、审批和配置前端 | 4-5 天 |
| 5 | 项目详情/看板/流水/通知联动 | 2-3 天 |
| 6 | 功能、权限、金额、并发、飞书和回归测试 | 2-3 天 |

## 18. 已确认项与开发门禁

本设计确认前不修改数据库和业务代码。以下三项已按用户确认结果固化到高保真原型：

1. 默认采用“费用业务审批通过即计入成本，出纳支付后计入已付”的权责分离口径。
2. 首期每张费用单只允许一次全额支付，不开放多次拆分支付；数据结构预留拆分能力。
3. 现有合同付款单切换到七级审批模板；合同收款单继续使用现有出纳确认流程。

可点击原型位于 [prototype/index.html](prototype/index.html)，重点覆盖项目费用列表、新增费用、费用详情、费用审批、审批岗位、审批流程、流程版本、路径演练及项目详情费用明细。

# v3.0.97 工时看板重设计方案

## 1. 设计背景

当前工时模块已经从早期“项目工时为主”的模式升级为新版工时体系：

- 工时类型分为 6 类：研发项目工时、技术服务工时、观摩推广工时、市场营销工时、管理工时、其他工时；
- 研发项目工时、技术服务工时为项目类工时，走项目负责人 → 项目审批人的二级审批；
- 观摩推广、市场营销、管理、其他为非项目类工时，不关联项目，按市场部门负责人或所属部门负责人审批；
- 工时日期按国家法定工作日历计算，支持调休工作日和法定假日；
- 工作台已有个人工时日历，工时看板不再重复展示日历热力带；
- 月度台账已有按项目汇总、明细下钻和打印能力，工时看板不再重复做项目排行和预立项处理入口；
- 项目经营、预算、成本、收付款已经归入“项目看板 / 经营分析”，不应继续混入工时看板。

因此，工时看板需要重新定位为：**专门回答“工时填报、审批、投入结构和异常在哪里”的管理视图**。

## 2. 设计原则

### 2.1 只看工时，不看金额

工时看板不展示：

- 成本预算；
- 实际成本；
- 人工费用金额；
- 合同收付款；
- 项目毛利；
- 项目经营收入。

这些内容保留在“项目看板 / 经营分析 / 项目详情”中。

### 2.2 项目类和非项目类必须分开看

新版工时中，“研发项目工时 / 技术服务工时”和“观摩推广 / 市场营销 / 管理 / 其他”业务含义不同：

- 项目类工时用于看项目投入、项目负责人、项目审批效率；
- 非项目类工时用于看部门事务、市场活动、会议管理、请假等非项目占用。

看板必须把两类工时明确分层，避免非项目工时混入项目排行。

### 2.3 先发现异常，再看结构，再下钻明细

页面顺序按管理者真实使用路径组织：

1. 先看是否有漏填、待审、驳回等填报和审批健康情况；
2. 再看工时投向：项目类 / 非项目类、部门、人员、类型；
3. 最后点击项目、部门、人员、日期进入明细或月度台账。

### 2.4 复用国家法定工作日历

所有“应填、漏填、填报率”必须基于国家法定工作日历：

- 调休周末算应填；
- 法定假日不算应填；
- 未配置日期回退为周一至周五。

## 3. 页面定位

页面名称：**工时看板**

页面一句话说明：

> 查看工时填报完成度、项目/非项目投入结构、项目阶段占比和异常工时。

核心用户：

- 工时管理员；
- 部门负责人；
- 项目负责人；
- 具备工时看板权限的管理者。

权限口径：

- 页面可见：`reports:VIEW`
- 导出：`reports:EXPORT`
- 数据范围：沿用 RBAC 数据范围，支持仅本人、负责项目、本部门及下级、全部数据。

## 4. 信息架构

新版工时看板分为 4 个区域：

```text
┌──────────────────────────────────────────────────────────────┐
│ A. 筛选区：时间 / 部门 / 人员 / 项目 / 工时类型 / 审批状态       │
├──────────────────────────────────────────────────────────────┤
│ B. 工时健康总览：已审批人天、填报完成率、漏填、待审批、驳回       │
├───────────────────────────────┬──────────────────────────────┤
│ C. 投入结构：工时类型 / 项目类与非项目类                         │
├───────────────────────────────┬──────────────────────────────┤
│ D. 项目工时阶段占比             │ E. 各项目阶段占比柱状图         │
├───────────────────────────────┴──────────────────────────────┤
│ F. 部门投入排行 / 人员工时排行                                  │
└──────────────────────────────────────────────────────────────┘
```

## 5. 页面详细设计

### 5.1 筛选区

筛选区采用紧凑横向布局，避免当前页面筛选项占用过多高度。

字段：

| 筛选项 | 说明 |
| --- | --- |
| 时间范围 | 默认本月，可快速选择本月、上月、近 30 天、自定义 |
| 部门 | 使用部门树，选择上级部门时包含下级部门 |
| 人员 | 可按姓名筛选，人员来自飞书组织架构 |
| 项目 | 仅影响项目类工时；支持项目名称/编号搜索 |
| 工时类型 | 6 类工时 + 历史项目工时/管理工时/其他工时兼容值 |
| 审批状态 | 草稿、审批中、已通过、已驳回、已锁定 |
| 项目状态 | 可选；仅用于项目类工时筛选，不单独展示预立项关注区 |

按钮：

- 查询；
- 重置；
- 导出明细。

筛选区顶部保留一行口径说明：

> 工时天数按国家法定工作日历计算；项目阶段占比只统计项目类工时，部门与人员统计包含全部工时。

### 5.2 工时健康总览

展示 6 张 KPI 卡片：

| 指标 | 计算口径 | 目的 |
| --- | --- | --- |
| 已审批人天 | 当前范围内状态为已通过/已锁定的工时天数 | 看实际完成统计量 |
| 提交人次 | 当前范围内提交过工时的人员数 | 看参与覆盖 |
| 填报完成率 | 已填报工作日人次 / 应填工作日人次 | 看漏填风险 |
| 漏填工作日 | 已过工作日中未填报的人员-日期数量 | 看补填压力 |
| 待审批 | 当前范围内审批中的工时数量 | 看审批待处理压力 |
| 驳回率 | 已驳回条数 / 已提交条数 | 看填报质量 |

建议颜色：

- 正常：绿色；
- 待处理：琥珀色；
- 异常：红色；
- 信息：蓝绿色。

### 5.3 项目工时阶段占比

这是新版看板的核心结构组件，用来回答“项目类工时主要花在什么阶段”。

展现方式：

- 只统计研发项目工时、技术服务工时；
- 使用堆叠进度条展示项目工时在各阶段的整体占比；
- 下方用阶段排行展示每个阶段的人天和占比；
- 点击某个阶段后，打开该阶段工时明细或筛选明细列表。

默认阶段建议：

| 阶段 | 说明 |
| --- | --- |
| 需求调研 | 前期调研、需求沟通、资料整理 |
| 方案设计 | 技术方案、原型、设计评审 |
| 开发实施 | 开发、配置、实施、现场搭建 |
| 联调测试 | 联调、测试、问题修复 |
| 交付验收 | 交付、验收、培训 |
| 项目管理 | 项目会议、计划、协调、管理 |

如果系统中的项目阶段来自基础配置，则以配置项为准；以上为原型展示口径。

### 5.4 各项目阶段占比柱状图

审批积压在当前看板中使用价值较低，第二排右侧调整为“各项目阶段占比柱状图”。

展示规则：

- 只统计研发项目工时、技术服务工时；
- 按项目汇总阶段投入，默认展示项目工时 Top 10；
- 每个项目使用 100% 堆叠柱状图，展示需求调研、方案设计、开发实施、联调测试、交付验收、项目管理等阶段占比；
- 纵轴为项目名称，横轴为阶段百分比；
- 鼠标悬浮主单位展示百分比，并在括号中补充该阶段实际工时天数。

目的：

- 快速判断单个项目是否长期停留在某一阶段；
- 对比不同项目阶段投入结构是否异常；
- 辅助项目负责人查看研发/技术服务工时投入是否符合项目当前进度。

### 5.5 投入结构分析

#### 5.5.1 工时类型分布

图表：横向条形图或环形图。

必须固定展示 6 类新工时类型：

1. 研发项目工时；
2. 技术服务工时；
3. 观摩推广工时；
4. 市场营销工时；
5. 管理工时；
6. 其他工时。

历史值 `PROJECT / MANAGEMENT / OTHER` 归入“历史工时”或按兼容映射展示，避免重复项。

#### 5.5.2 项目类 / 非项目类占比

项目类：

- 研发项目工时；
- 技术服务工时。

非项目类：

- 观摩推广工时；
- 市场营销工时；
- 管理工时；
- 其他工时。

该图用于看团队时间是否过多消耗在非项目事务上。

#### 5.5.3 部门投入排行

按部门汇总全部工时。

支持：

- 一级部门汇总；
- 点击部门下钻到子部门；
- 选择上级部门时自动包含下级部门。

#### 5.5.4 人员投入排行

按人员汇总全部工时。

建议字段：

- 人员；
- 部门；
- 已审批人天；
- 审批中人天；
- 漏填天数；
- 驳回条数。

这样能同时看到“投入多”和“填报质量差”的人员。

### 5.6 本版明确移除的区域

根据页面确认意见，工时看板不展示以下区域：

- 工时日历热力带：个人和日期填报提醒已经由工作台工时日历承载；
- 项目投入与预立项关注：项目维度汇总、明细、打印由“月度台账”承载；预立项处理由项目管理和项目详情承载；
- 转管理工时留痕：保留在工时台账、项目预立项处理或工时详情中查看。

## 6. 下钻交互

所有图表都应可点击下钻，而不是只展示图片。

| 点击位置 | 下钻结果 |
| --- | --- |
| KPI 卡片“漏填工作日” | 打开漏填人员/日期明细 |
| KPI 卡片“待审批” | 跳转工时审批并带筛选条件 |
| 项目阶段占比某个阶段 | 筛选该阶段的项目工时明细 |
| 工时类型图 | 筛选该工时类型的明细 |
| 部门排行 | 下钻到部门人员明细 |
| 人员排行 | 打开该人员工时明细 |

## 7. 空状态与异常状态

### 7.1 无数据

文案：

> 当前筛选范围暂无工时数据。可以放宽时间范围或切换部门后重新查询。

### 7.2 工作日历未维护

文案：

> 当前年份未维护国家法定工作日历，系统暂按周一至周五计算。建议在系统管理 → 基础配置 → 工作日历中补充。

### 7.3 审批人缺失

工时看板不再展示审批积压明细；审批人缺失、节点异常等审批问题回到“工时审批”和“通知中心”处理，避免看板同时承担审批工作台职责。

## 8. 视觉设计方案

### 8.1 设计方向

主题：**工时结构雷达**

看板不是普通报表，而是管理者扫一眼就知道“谁没填、谁没批、工时主要消耗在哪类工作和项目阶段”的结构雷达屏。

视觉关键词：

- 清爽；
- 管理视角；
- 数据密度高但不拥挤；
- 绿色代表完成，红色代表缺口，琥珀色代表待处理。

### 8.2 色彩 Token

| Token | 颜色 | 用途 |
| --- | --- | --- |
| `radar-ink` | `#12201F` | 主文字 |
| `radar-muted` | `#667A76` | 次级文字 |
| `radar-green` | `#1F8A5B` | 已完成、已填报 |
| `radar-amber` | `#D88918` | 待处理、审批中 |
| `radar-red` | `#C94A3A` | 漏填、驳回、超时 |
| `radar-teal` | `#0F766E` | 主操作和强调 |
| `radar-blue` | `#3A6EA5` | 审批流和趋势 |
| `radar-bg` | `#F5F8F7` | 页面背景 |

### 8.3 字体与数字

- 标题：沿用系统中文字体，不引入外部字体，避免部署复杂度；
- 数字：使用等宽数字样式，保证 KPI、表格数字对齐；
- 图表标签保持中文，不再出现枚举英文。

## 10. 开发拆分建议

### 阶段一：接口口径整理

- 调整 `/api/v1/reports/workload`，补齐新版看板所需指标；
- 移除前端工时看板中的成本、预算相关展示；
- 工时类型分布固定兼容 6 类新类型和历史类型。
- 新增项目阶段占比数据：只统计研发项目工时和技术服务工时。

### 阶段二：页面重排

- 重做筛选区；
- 新增工时健康总览；
- 将“工时类型分布”和“项目类 / 非项目类”放在第一排；
- 将“项目工时阶段占比”和“各项目阶段占比柱状图”放在第二排；
- 下方保留部门投入排行和人员工时排行；
- 移除项目投入与预立项关注区域。

### 阶段三：下钻与联动

- 项目阶段下钻；
- 类型、部门、人员、项目点击下钻；
- 导出沿用筛选条件。

### 阶段四：回归

重点回归：

- 部门含下级；
- RBAC 数据范围；
- 6 类工时类型不重复；
- 项目类/非项目类分流；
- 项目阶段占比只统计项目类工时；
- 月度台账和工时看板统计口径一致；
- 导出权限。

## 11. 验收标准

1. 工时看板不再展示成本、预算、金额和经营类指标。
2. 工时类型分布只展示 6 类新版工时类型，历史类型不重复显示。
3. 项目排行只统计研发项目工时和技术服务工时。
4. 部门、人员统计包含全部工时类型。
5. 填报完成率和漏填按国家法定工作日历计算，但页面不展示工作日历热力带。
6. 页面不再展示审批积压图表。
7. 页面展示项目工时阶段占比和各项目阶段占比柱状图，且只统计研发项目工时和技术服务工时。
8. 页面不展示项目投入与预立项关注区，相关能力回到月度台账和项目管理。
9. 所有筛选项都受 RBAC 数据范围控制。
10. 页面在桌面端无横向滚动；移动端可降级为纵向卡片布局。

## 12. 生产补充调整：筛选项与填报完成率落地

根据生产页面走查，真实系统必须与 v3.0.97 原型保持一致，补齐以下落地要求：

- 工时看板筛选区包含：部门、人员、项目、工时类型、审批状态、开始日期、结束日期。
- 顶部健康指标展示“填报完成率”，计算口径为：筛选范围内已提交/审批中/已通过/已锁定工时覆盖的国家法定工作日人次 ÷ 筛选范围内应填国家法定工作日人次。
- 草稿、已驳回、已撤回默认不计入填报完成；当用户显式选择审批状态时，填报完成率按当前审批状态筛选后的覆盖天数联动展示。
- 查询图表、顶部指标和导出明细共用同一组筛选条件。
- 部门筛选统一口径：项目类工时按项目所属部门统计，非项目类工时按填报人所属部门统计。

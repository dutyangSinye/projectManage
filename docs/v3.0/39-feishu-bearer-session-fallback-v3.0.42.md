# 综合项目管理系统 v3.0.42：飞书登录令牌双通道认证

- 版本：v3.0.42
- 日期：2026-09-05
- 状态：已实现、已测试、已发布

## 1. 生产故障证据

新服务器连续多次出现同一请求序列：

1. `POST /api/v1/auth/feishu/exchange` 返回 200，说明飞书授权码有效且本地用户已识别。
2. 紧接着 `GET /api/v1/me` 返回 401，说明飞书内置浏览器没有保留 HTTP IP 地址下的 Session Cookie。
3. 显式设置 Fetch Cookie 凭据后现象不变，确认不能继续依赖 WebView Cookie 策略。

## 2. 修复方案

- 保留现有 HttpOnly Session Cookie，兼容普通浏览器和后续 HTTPS 部署。
- 飞书换码成功后额外返回由 `FEISHU_SESSION_SECRET` 签名的短期访问令牌，有效期与会话一致，默认 8 小时。
- 前端将令牌保存在当前页面会话的 `sessionStorage`，所有 API、导出、上传、预览和下载请求通过 `Authorization: Bearer <token>` 显式携带。
- 后端认证中间件优先读取 Cookie；Cookie 不存在时验证 Bearer 令牌并恢复当前用户。
- 401 时立即清除本地失效令牌；登出时同时清除 Cookie 和页面会话令牌。
- 令牌只包含本地用户 ID、版本和签发时间，不包含飞书密钥、人员资料或权限数据。用户停用后即使令牌未过期也无法通过当前用户校验。

## 3. 接口契约

### `POST /api/v1/auth/feishu/exchange`

输入：

```json
{"code":"飞书一次性授权码"}
```

输出：

```json
{"ok":true,"user_id":1,"access_token":"签名令牌","expires_in":28800}
```

错误：飞书未配置返回 503；换码失败返回 401；用户停用返回 403。

### 受保护接口

支持两种认证方式：HttpOnly Session Cookie，或 `Authorization: Bearer <access_token>`。签名无效、过期或用户停用均返回 401。

## 5. 验收标准

1. 不接受 Cookie 的客户端在换码成功后可凭 Bearer 令牌访问 `/api/v1/me`。
2. 缺少、伪造或过期令牌仍返回 401。
3. Cookie 登录路径保持兼容。
4. 页面刷新后当前飞书页面会话仍可登录，关闭该页面后不长期保存令牌。
5. 导出和附件请求均携带同一认证令牌。
6. 登出或收到认证 401 后清除本地令牌。

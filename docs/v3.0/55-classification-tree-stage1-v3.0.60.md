本次为“全量分阶段推进”的第 1 阶段（基础层）。第 2 阶段为单据层（合同付款一级复核、项目费用简化、人工成本结转、费用复核页），第 3 阶段为看板层（项目详情四分区与新口径看板）。

## 1. 为什么要改

原型明确“项目分类树、预算项模板和成本分类树统一维护，不再使用扁平静态下拉框”。改造前的实现存在三个问题：

1. 项目类型是一张扁平下拉（研发项目 / 课题项目 / 实施项目 / 观摩项目），无法表达“大类 + 小类”两级口径。
2. 成本分类只以文本 `cost_major` / `cost_minor` 落在预算项模板上，没有可维护的分类树，名称靠人工对齐。
3. 项目类型这个扁平分类与新版原型口径冲突，继续存在会让同一概念出现两套入口。

## 2. 数据模型

### 新增列（幂等 `ALTER TABLE`，由 `upgrade_schema()` 补齐）

| 表 | 列 | 说明 |
| --- | --- | --- |
| `config_options` | `parent_id` | 上级分类 ID，顶层为 NULL |
| `config_options` | `level` | 层级，1 为顶层，2 为子级 |
| `config_options` | `path` | 物化路径，形如 `/12/`，便于后续扩展多层 |
| `config_options` | `is_leaf` | 是否有下级 |
| `projects` | `project_sub_category` | 项目小类编码，可为空 |
| `budget_item_templates` | `cost_minor_options` | 可归集成本小类候选（JSON 文本） |
| `project_budget_items` | `cost_minor_options` | 由模板快照复制，保证历史项目口径稳定 |

`cost_minor_options` 采用 JSON 文本而不是关联表，原因是它只是“候选集合”的快照，随预算项模板一起复制到项目预算项，用关联表会让新旧口径同步变得脆弱。

### 两棵树

**项目分类树**（`project_category` → `project_sub_category`）

| 大类 | 小类 |
| --- | --- |
| 经营项目 `BUSINESS_PROJECT` | 委托研发、设备销售、技术服务、机器人施工、设备租赁 |
| 研发项目 `RND_PROJECT` | 自主研发、外部申报 |

**成本分类树**（`cost_category` → `cost_sub_category`）

| 大类 | 小类示例 |
| --- | --- |
| 材料成本 | 材料成本 |
| 人工成本 | 人工成本 |
| 机械使用费 | 机械使用费 |
| 其他直接/间接费用 | 差旅费、运输、包装费、技术服务费、修理费、招标投标费、劳务费、检测试验费、安全经费、临时设施费、办公费、保险费、水、电、燃气费、租赁费、折旧费、其他（共 15 项） |
| 加工成本、工程分包成本 | 内部加工费、外部加工费、工程分包成本 |
| 设备采购 | 设备采购 |
| 部门制造费用 | 部门制造费用 |

共 7 个大类、23 个小类。

| 预算项 | 成本大类 | 默认成本小类 | 可归集小类 |
| --- | --- | --- | --- |

| 材料、设备采购 | 材料成本 | 材料成本 | 材料成本、设备采购 |

| 委托、分包、外包费用 | 加工成本、工程分包成本 | 工程分包成本 | 内部加工费、外部加工费、工程分包成本 |
| 差旅费用 | 其他直接/间接费用 | 差旅费 | 差旅费 |
| 包装、运输费用 | 其他直接/间接费用 | 运输 | 运输、包装费 |

“材料、设备采购”等预算项允许跨成本大类归集，因此校验规则只要求候选小类是成本分类树里存在的有效小类，不强制挂在所选成本大类之下。

## 3. 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/config/classifications` | 登录 | 读取两棵分类树（仅启用项），供业务表单联动 |
| GET | `/api/v1/admin/config/classifications` | `configuration:VIEW` | 读取两棵分类树（含停用项），供基础配置页维护 |
| POST/PATCH/DELETE | `/api/v1/admin/config/options` | `configuration:CREATE/EDIT/DELETE` | 分类节点维护，新增/修改时校验层级归属 |
| GET | `/api/v1/projects/page` | `projects:VIEW` | 新增 `project_sub_category` 筛选参数 |

新增错误码：

- `INVALID_CONFIG_PARENT`：上级分类不存在或类型不匹配。
- `CONFIG_OPTION_HAS_CHILDREN`：分类下仍有子项，禁止删除。
- `INVALID_PROJECT_SUB_CATEGORY`：项目小类不属于所选大类或已停用。
- `INVALID_COST_MINOR_OPTION`：预算项候选小类不是成本分类树里的有效小类。

## 4. 扁平 `project_type` 分类下线

- `CONFIG_CATEGORY_LABELS` / `DEFAULT_CONFIG_OPTIONS` 移除 `project_type`。
- 迁移阶段直接删除 `config_options` 中 `category = 'project_type'` 的历史记录（项目本身已归一到两个内置大类，无引用依赖）。
- 项目大类统一存 `projects.project_type`（取值 `BUSINESS_PROJECT` / `RND_PROJECT`），小类存 `projects.project_sub_category`。
- 历史值按别名表归并：课题项目 / 自主研发 / 外部申报 → 研发项目；实施项目 / 观摩项目 → 经营项目。

## 5. 前端

### 基础配置页

- 左侧分类列表改为只列平铺分类（项目阶段、工时类型、工作状态、项目状态），分类树不再混在平铺列表里。
- 新增“分类体系”卡片：项目分类树 / 成本分类树两个页签，树形展示大类与小类，支持新增大类、在大类下加小类、编辑、启用/停用、删除。
- 分类节点弹窗展示所属分类树与上级大类（只读），编码创建后不可修改。
- 预算项模板表格新增“可归集小类”列；模板弹窗的成本大类、默认成本小类改为分类树下拉，并支持勾选多个可归集小类。
- 页面说明明确“经营项目和研发项目默认使用同一套 8 个预算项”。

### 项目管理

- 新增/编辑项目表单：项目类型改为“项目大类 + 项目小类”，小类按所选大类联动；切换大类时自动清空不属于新大类的小类。
- 列表筛选：新增项目小类筛选，未选大类时禁用；切换大类时自动清空失效的小类条件。
- 列表“分类”列展示大类标签 + 小类名称。

### 其他

- 工时编辑、管理端工时编辑、项目看板筛选中原“项目类型”统一改称“项目大类”，选项来源改读分类树。
- 工作台项目行展示“大类 / 小类”。
- 项目详情基本信息新增“项目小类”。
- 应用启动时读取一次分类树接口，普通用户也能正确展示大类小类名称；分类树未加载时使用内置兜底名称。

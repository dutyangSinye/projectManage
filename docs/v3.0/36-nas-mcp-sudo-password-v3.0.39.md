# 综合项目管理系统 v3.0.39：NAS MCP 普通 sudo 兼容

- 版本：v3.0.39
- 日期：2026-09-05
- 状态：已确认，进入实现

## 1. 问题

旧 NAS 的部署账号具备普通 `sudo` 权限，但没有配置免密 `sudo`。NAS MCP 原先所有远程命令固定使用 `sudo -n`，因此健康检查可通过，Docker 状态和发布操作却会因需要密码而失败。

## 2. 方案

- 当 MCP 已配置 SSH 密码且远程命令包含 `sudo -n` 时，先通过标准输入执行一次 `sudo -S -v` 建立短时授权缓存。
- 原有命令继续使用 `sudo -n`，不在远程命令参数、日志或返回结果中拼接密码。
- 未配置密码时继续使用原有免密 sudo/密钥路径。
- 仅用于 NAS MCP 的远程运维，不改变应用运行时认证和业务数据。

## 3. 验收标准

1. 普通 sudo 账号可通过 MCP 查看 Docker Compose 状态。
2. 普通 sudo 账号可通过 MCP 完成应用发布。
3. SSH 密码不出现在远程命令字符串、标准输出和错误输出中。
4. 原有免密 sudo 部署仍可正常工作。

# 综合项目管理系统 v3.0.43：飞书 WebView 登录兼容修复

## 问题结论

生产请求日志显示，飞书客户端已成功取得授权码，后端换码接口也返回 200；失败发生在换码后的当前用户请求。HTTP IP 场景下 Cookie 未被飞书 WebView 保留，标准 `Authorization` 请求头也未被后端识别，因此 `/api/v1/me` 返回 401。

## 实现

- 登录换码后继续签发 8 小时有效的服务端签名令牌。
- 前端同时发送 `Authorization: Bearer ...` 和 `X-Xinye-Session: ...`。
- Nginx 显式将两个认证头转发给后端。
- 后端按 Session Cookie、标准认证头、兼容认证头的顺序识别用户。
- 认证日志仅记录凭据是否存在、校验是否成功和命中的认证通道，不记录令牌或用户敏感信息。
- 迁移后若 `SYSTEM_ADMIN_USER_IDS` 指向当前库中不存在的旧用户，不再阻止首位成功登录的飞书用户初始化为系统管理员。

## 安全边界

- 兼容令牌与原 Bearer 令牌使用相同的服务端签名、盐值和有效期校验。
- 伪造、过期或签名不一致的令牌均返回 401。
- 401 和主动退出会清除飞书 WebView 中的临时令牌。
- 令牌保存在 `sessionStorage`，关闭当前 WebView 会话后不会长期保留。

## 验证范围

- 标准 Bearer 认证。
- 兼容认证头认证。
- 标准头无效时回退兼容头。
- 缺少令牌和伪造令牌拒绝访问。
- 前端 TypeScript 检查与生产构建。
- 后端业务回归与 NAS MCP 回归。

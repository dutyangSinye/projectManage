# v3.0.90 移动端工时填报与工作台顺序优化设计

日期：2026-10-02
状态：已确认执行
适用系统：综合项目管理系统 v3.0.90
类型：快速通道（UI/交互迭代）

## 1. 需求

1. 优化移动端工时填报的 UI 和交互。
2. 工作台（移动端）把“工时填报”放到最上面，“项目管理”的内容放到下面。

## 2. 现状问题

- 工作台页面顺序为先“我的项目（项目负责人视角）”，后“我的工时（员工视角）”。移动端打开工作台时首先看到的是项目经营概况大表格，需要向下滚动很长距离才能找到“＋ 填报工时”。
- 移动端工时填报页（新增/修改工时）虽然已经是单列表单，但：
  - 输入框、下拉框高度偏小，触摸目标不足；
  - 日期字段在窄屏上较为拥挤；
  - 保存草稿 / 保存并提交按钮位于表单末尾，长表单需要滚到底部才能提交；
  - 缺少清晰的当前选择摘要（项目、工时类型、天数）。

## 3. 设计方案

### 3.1 工作台顺序（仅移动端 ≤640px）

不改动 DOM 结构，使用 CSS 排序实现，保证桌面端顺序完全不变：

- 移动端工作台纵向顺序：页面标题 → 工时填报（我的工时区块）→ 项目管理区块（我的项目）。
- 桌面端保持现有顺序：标题 → 我的项目 → 我的工时。

### 3.2 移动端工作台工时区块

- “我的工时”区块标题区在移动端改为上下堆叠，右上角“＋ 填报工时”变为整行主按钮并对齐到顶部，进入工作台第一屏即可直接点按。
- 指标卡在移动端保持两列，间距收紧。
- “待处理事项”“最近工时”保持列表卡片形式，点击区域整行可点。

### 3.3 移动端工时填报页

- 页面增加标识类 `worklog-editor-page`，仅在该页生效。
- 表单字段在移动端单列，输入框、下拉框字号提升到 16px（避免 iOS 聚焦自动缩放），最小高度提升到 46px，扩大触摸目标。
- 日期类字段保持整行宽度，避免窄屏挤压。
- 底部操作区改为吸底（sticky）工具条：保存并提交为整行主按钮，保存草稿、取消并排；带 `env(safe-area-inset-bottom)` 安全区适配，避免被系统手势条遮挡。
- 项目选择器：移动端菜单最大高度适配视口，选项保持 ≥52px 触摸高度，搜索框整行。
- 校验错误（日期区间、跨月、重复填报）仍由既有逻辑输出，移动端提示条置顶显示，不改变校验规则。

## 4. 影响范围（关联回归）

- 工作台桌面端顺序与样式：必须保持不变。
- 工时填报校验规则（法定工作日天数、跨月、同一天重复）：不改动，回归验证。
- 桌面端工时填报页布局：仅新增页面标识类，桌面样式不受影响。
- 其他页面（我的工时、工时审批、工时看板）：不改动。

## 5. 验收标准

- 390×844 移动端：工作台第一屏即可看到并使用“填报工时”入口；无横向滚动。
- 移动端工时填报页：表单无横向溢出，提交按钮无需滚动到底部即可触达。
- 桌面端（≥1024px）：工作台仍为“我的项目”在上、“我的工时”在下；工时填报页与改动前一致。

# v3.0.91 填报工时项目选择器体验优化设计

日期：2026-10-02
状态：已确认执行
适用系统：综合项目管理系统 v3.0.91
类型：快速通道（交互优化 + 缺陷修复）

## 1. 反馈问题

工时填报页的“项目选择器”选起来很麻烦，选完项目后还要再点一次选择器才能选中。

## 2. 原因分析

1. 选择器外层使用 `<label>` 包裹。`<label>` 的激活行为会把它内部被认定为“标注控件”的元素再激活一次，在不同内核（尤其飞书内置浏览器 / iOS WebView）里表现不一致，容易出现一次点击被拆成两次交互、选择结果看起来没有立即生效。
2. 选项行把“项目编码”放在主标题位置、“项目名称”放在次要小字。项目编码是 `PRJ-AUTO-xxxxxxxx` 形式，无法辨识，用户难以确认自己选的是不是想要的项目，只能反复打开列表核对。
3. 选项按钮上没有处理 `mousedown`，触屏设备上第一次点按可能只用于让搜索框失焦，点击不落到选项上。
4. 移动端菜单是绝对定位弹层，靠近页面底部时会被视口裁掉，需要先滚动页面才能看到完整列表。
5. 列表没有把当前已选项目滚动到可见位置，长列表里需要手动翻找。

## 3. 优化方案

### 3.1 结构修复

- 选择器外层由 `label` 改为 `div.project-picker-label` 加独立标签文本，彻底去掉 `label` 激活行为带来的二次点击；标签字号、颜色、间距与表单其他字段保持一致。
- 选项行增加 `mousedown.prevent`，保证触屏第一次点按就落到选项上，不会再被搜索框失焦吃掉。
- 菜单与选项容器增加引用与键盘处理，行为更可控。

### 3.2 可辨识性

- 选项行改为“项目名称（主）+ 编码 · 项目类型（次）”，名称允许换行显示，不再因为单行省略而看不清。
- 触发按钮同样改为“项目名称（主）+ 编码 · 类型 · 提示（次）”，选完即可直接确认，不需要再打开列表核对。
- 当前已选项增加高亮底色与左侧色条，勾选标记保留。

### 3.3 移动端交互

- 移动端项目选择菜单改为底部弹出面板（贴底、圆角、最大高度 72vh、安全区适配），列表在面板内部滚动，不会再被视口裁切，也不会因为页面位置不同而跑到屏幕外。
- 面板内部列表可独立滚动；点选后立即收起。

### 3.4 便捷操作

- 打开选择器时自动把当前已选项目滚动到可见位置。
- 桌面端（精细指针）打开时自动聚焦搜索框，可直接输入关键字。
- 支持键盘：搜索框 `Enter` 选中当前列表第一项、`Esc` 关闭；触发按钮 `Esc` 关闭。
- 点击选择器以外的任意位置自动关闭（沿用既有文档级点击收起逻辑）。

## 4. 影响范围（关联回归）

- 工时填报页项目选择相关：新增/编辑工时选择项目、实际审批人提示、项目类工时二级审批逻辑 —— 本次仅调整选择器交互，不改审批口径。
- 非项目类工时（不显示项目选择器）不受影响。
- 其他页面（我的工时、工时审批、工时看板、项目管理）不涉及。

## 5. 验收标准

- 桌面端：点击选项一次即完成选择，触发按钮立即显示新项目名称；`Enter` 可选中第一项；点击外部收起。
- 移动端（390×844 与 390×520）：点按选项一次即完成选择；面板完整显示在视口内，列表在面板内滚动；页面无横向溢出。
- 选择器标签“项目”正常显示，与表单其他字段样式一致。

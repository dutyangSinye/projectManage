## 1. 设计目标

本次新增三个财务经营视图，三者职责完全分离：

1. **回款台账**：面向项目负责人、经营管理和财务，按项目/合同跟踪合同应收、累计已收、实际未收、上月计划与实际、本月计划与实际、项目进展和预计完成时间。
2. **付款计划**：面向经办人、部门负责人、财务和管理层，按资金计划周期汇总未来拟付款事项，支持合同付款、项目费用、研发费用、服务费、采购货款、员工/个人收款等场景。
3. **经营分析**：面向管理层和项目负责人，独立展示回款计划完成率、付款计划、资金净流入、逾期未收、风险项目排行和部门/类别结构分析。

设计原则：

- 不重复造 Excel，尽量复用系统已有项目、合同阶段、合同收款、合同付款、项目费用和费用复核数据。
- 使用者只补充系统无法自动获得的信息，例如本月计划、项目进展、预计完成时间、资金用途说明、是否加急等。
- 计划层与审批层分离：付款计划只是资金计划，不等同于付款审批单；实际付款仍走合同付款、项目费用或其他已有审批流程。
- 支持“收款方为个人”的真实业务场景，不强制所有付款对象先建供应商。
- 回款台账和付款计划是操作型台账，不混放经营分析指标；资金流、趋势、风险和排行统一放到独立“经营分析”页面。
- **回款计划、付款计划均不走审批**：两者只作为经营计划/台账维护，不生成待审批任务，不触发现有合同收付款、费用复核或飞书审批流程。

## 3. 回款台账设计

### 3.1 页面定位

回款台账不是新增收款单，而是按“项目 + 收入合同”汇总回款进度，并提供月度计划维护。

适合回答：

- 本月计划回款多少？
- 上月计划回款完成了多少？
- 哪些项目实际未收金额较大？
- 哪些项目预计完成时间接近但回款未完成？
- 项目负责人承诺的本月回款计划是什么？

### 3.2 列表字段

| 字段 | 来源/规则 | 是否可编辑 |
|---|---|---|
| 项目名称 | 项目主数据 | 否 |
| 合同名称 | 收入合同 | 否 |
| 客户全称 | 客户主数据快照/合同客户 | 否 |
| 合同总额（含税） | 收入合同含税金额 | 否 |
| 合同应收金额 | 收入合同阶段应收金额合计；无阶段时等于合同总额 | 否 |
| 累计已收金额 | 已审批且未冲销的合同收款单金额合计 | 否 |
| 实际未收金额 | 合同应收金额 - 累计已收金额 | 否 |
| 上月收款计划 | 上月维护的计划金额 | 否，历史可按权限更正 |
| 上月实际回款 | 上月已审批收款单金额 | 否 |
| 本月收款计划 | 本月计划金额 | 是 |
| 本月实际回款 | 本月已审批收款单金额 | 否 |
| 项目进展及计划 | 项目负责人/经营人员维护 | 是 |
| 预计完成时间 | 计划完成或验收时间 | 是 |
| 填表人 | 最近维护人 | 否 |
| 责任部门 | 项目所属部门 | 否 |
| 备注 | 补充说明 | 是 |

### 3.3 顶部汇总卡片

按当前筛选范围展示：

- 合同总额
- 合同应收金额
- 累计已收金额
- 实际未收金额
- 本月计划回款
- 本月实际回款
- 本月计划完成率 = 本月实际回款 / 本月收款计划
- 逾期未收金额

### 3.4 筛选项

筛选区使用紧凑布局：

- 统计月份：默认本月。
- 部门：组织树，包含下级部门。
- 项目负责人。
- 项目名称/合同名称/客户名称关键词。
- 客户。
- 项目状态。
- 回款状态：全部、未开始、部分回款、已完成、逾期未收。
- 仅看我负责。

### 3.5 操作

| 操作 | 说明 |
|---|---|
| 查询 | 按筛选刷新数据 |
| 编辑本月计划 | 批量或单行维护本月收款计划、项目进展、预计完成时间、备注 |
| 查看合同 | 跳转合同详情 |
| 查看回款明细 | 展开/弹窗展示该合同的所有收款单 |
| 导出台账 | 导出当前筛选结果，字段顺序对齐财务台账 |
| 导入本月计划 | 可选能力，用模板批量导入本月收款计划和项目进展 |

### 3.6 自动计算口径

```text
合同应收金额 = 收入合同阶段计划金额合计
累计已收金额 = 已审批且未冲销的合同收款单金额合计
实际未收金额 = 合同应收金额 - 累计已收金额
上月实际回款 = 收款日期在上月的已审批收款单金额合计
本月实际回款 = 收款日期在本月的已审批收款单金额合计
本月计划完成率 = 本月实际回款 / 本月收款计划
```

若合同没有阶段，系统允许以合同总额作为应收金额，但列表显示“未配置阶段”提示，提醒后续补阶段。

### 3.7 回款预警

| 预警 | 规则 |
|---|---|
| 本月计划未完成 | 本月计划 > 0，月底前 5 天实际回款小于计划 |
| 逾期未收 | 收入合同阶段计划收款日早于今天，阶段剩余应收 > 0 |
| 预计完成临近未收 | 预计完成时间 30 天内，实际未收金额 > 0 |
| 长期未维护计划 | 进入本月第 5 个工作日后，本月计划为空 |

预警先在页面展示；是否飞书推送可作为通知策略开关，不默认打扰所有人。

## 4. 付款计划设计

### 4.1 页面定位

付款计划是“资金计划”，用于提前收集未来某周期内可能需要付款的事项。

它不是付款审批单，不直接写入“已付”，也不直接影响项目成本；真正发生付款时，仍然需要从计划发起或关联：

- 合同付款单；
- 项目费用单；
- 人工成本结转；
- 后续如有借款/报销/个人劳务付款模块，也从计划关联。

### 4.2 付款计划列表字段

参考现有飞书表格，建议字段如下：

| 字段 | 说明 | 是否必填 |
|---|---|---|
| 资金计划所属周期 | 年月，例如 2026-10 | 是 |
| 部门 | 经办人所属部门或项目所属部门 | 是 |
| 经办人 | 飞书人员 | 是 |
| 付款类别 | 采购货款、研发费用、服务费、差旅费、报销款、劳务费、税费、其他 | 是 |
| 来源类型 | 支出合同阶段、项目费用、人工成本结转、手工计划 | 是 |
| 项目 | 可选；项目相关付款必填 | 视场景 |
| 支出合同 | 来源为支出合同阶段时必填 | 视场景 |
| 合同阶段 | 来源为支出合同阶段时必填 | 视场景 |
| 收款方类型 | 公司、供应商、员工、外部个人、其他 | 是 |
| 收款方名称 | 公司全称、供应商名称、员工姓名或个人姓名 | 是 |
| 计划付款金额 | 本周期计划付款金额 | 是 |
| 付款方式 | 银行转账、现金、票据、其他 | 是 |
| 计划付款日期 | 具体预计付款日 | 建议必填 |
| 资金用途说明 | 付款用途、阶段说明或特殊事项 | 是 |
| 是否合同/财务相关 | 对应原“合同财务…”字段，可改名为“是否关联合同/财务资料” | 是 |
| 是否加急 | 是/否 | 是 |
| 备注 | 特殊事项说明 | 否 |
| 计划状态 | 草稿、已提交计划、已转付款、已取消 | 系统生成 |
| 实际付款状态 | 未付款、审批中、已付款、已取消 | 系统生成 |

### 4.2.1 来源类型必填规则

| 来源类型 | 项目 | 支出合同 | 合同阶段 | 规则 |
|---|---|---|---|---|
| 支出合同阶段 | 自动带出/可校验 | 必填 | 必填 | 必须选择支出合同及其合同阶段，项目由合同自动带出；用于阶段性付款计划 |
| 项目费用 | 必填 | 不填 | 不填 | 必须选择项目，用于尚未形成合同阶段的费用计划 |
| 手工计划 | 可空 | 可空 | 可空 | 用于临时资金计划、个人付款或暂无法归属项目合同的事项 |

### 4.3 收款方支持个人

付款计划的收款方不能只绑定供应商。设计为：

| 收款方类型 | 适用场景 | 带出/填写规则 |
|---|---|---|
| 供应商 | 采购、分包、外包、服务商付款 | 从供应商管理选择，带出默认收款账户，可临时修改为本计划快照 |
| 公司 | 非供应商但属于公司主体，例如一次性合作单位 | 可从客户/供应商/手工公司名称中选择或录入；建议后续沉淀为供应商 |
| 员工 | 员工报销、备用金、垫付款、差旅款 | 从飞书组织人员选择，带出员工姓名和部门；银行卡信息可在本计划录入快照，不强制进入供应商 |
| 外部个人 | 专家费、劳务费、临时个人服务、个人收款 | 手工填写姓名、身份证/证件后四位（可选）、收款银行、账号、手机号（可选） |
| 其他 | 暂不能归类的付款对象 | 必须填写说明，后续财务复核时要求归类 |

个人收款方字段建议：

| 字段 | 员工 | 外部个人 | 说明 |
|---|---|---|---|
| 姓名 | 飞书带出 | 手工填写 | 必填 |
| 所属部门 | 飞书带出 | 可选 | 员工必有 |
| 证件信息 | 不默认要求 | 可选填后四位 | 不建议在列表展示完整证件 |
| 收款银行 | 可填写 | 可填写 | 生成付款单时形成快照 |
| 收款账号 | 可填写 | 可填写 | 脱敏展示，仅授权人员查看完整值 |
| 联系方式 | 可选 | 可选 | 外部个人可用 |
| 付款事由 | 必填 | 必填 | 便于财务判断合规性 |

安全规则：

- 列表只显示账号后四位。
- 飞书通知不展示完整账号和证件。
- 完整账号仅付款编辑、付款审批、财务复核、系统管理员中特定授权人员可查看。
- 个人收款方不自动进入供应商库，避免把临时个人污染供应商主数据。

### 4.4 新增付款计划交互

新增弹窗分四段：

1. **计划基础信息**
   - 资金计划周期、部门、经办人、付款类别、计划付款日期、是否加急。
2. **业务来源**
   - 可选“从支出合同阶段选择 / 从项目费用选择 / 手工新增计划”。
   - 从合同阶段选择时，自动带出项目、合同、阶段、阶段剩余应付、供应商。
   - 从项目费用选择时，自动带出项目、费用类型、金额、申请人。
3. **收款方与金额**
   - 先选收款方类型，再展示对应字段。
   - 收款方类型为个人时，展示个人字段，不要求供应商编码。
4. **用途与备注**
   - 资金用途说明、是否关联合同/财务资料、备注。

### 4.5 计划转付款

| 来源类型 | 转换动作 |
|---|---|
| 支出合同阶段 | 生成合同付款单，并带出项目、合同、阶段、收款方、金额、用途 |
| 项目费用 | 跳转项目费用单或费用复核流程 |
| 人工成本结转 | 跳转人工成本结转单 |
| 手工计划 | 按付款类别选择生成合同付款、项目费用或仅保留计划记录 |

转换后：

- 付款计划状态改为“已转付款”。
- 记录关联的付款单/费用单 ID。
- 实际付款状态跟随关联单据变化。

### 5.3 经营分析

经营分析是独立页面，不承担台账录入和付款计划维护，避免“回款台账”和“付款计划”混在同一资金流区域里。

```text
经营分析
┌ 筛选区：分析月份 / 部门树 / 项目负责人 / 项目状态 / 查询 / 导出分析 ┐
├ 资金流时间带：本月计划回款 | 本月实际回款 | 本月计划付款 | 逾期未收 ┤
├ 图表区
│ 月度收付趋势（近 6 个月）
│ 回款完成率
│ 资金净流入
│ 风险项目排行
│ 收款责任部门排行
│ 付款结构分析
└ 只读下钻：点击指标可跳到回款台账或付款计划对应筛选结果
```

经营分析指标：

| 指标 | 口径 |
|---|---|
| 本月计划回款 | 回款台账中本月计划金额合计 |
| 本月实际回款 | 本月已审批合同收款单金额合计 |
| 回款完成率 | 本月实际回款 / 本月计划回款 |
| 本月计划付款 | 付款计划中当前周期计划金额合计 |
| 资金净流入 | 本月实际回款 - 本月计划付款 |
| 逾期未收 | 已到期收入合同阶段剩余应收金额 |
| 风险项目排行 | 按逾期未收、预计完成临近、加急付款综合排序 |

## 6. 权限设计

新增菜单权限：

## 7. 导入导出模板

### 7.1 回款台账导出

字段顺序对齐当前财务表：

### 7.2 付款计划导入

必要字段：

资金计划所属周期、部门、经办人、付款类别、收款方类型、收款方名称、计划付款金额、付款方式、计划付款日期、资金用途说明、是否关联合同/财务资料、是否加急、备注。

可选匹配字段：

项目名称、合同名称、合同阶段名称。

导入校验：

- 周期必须为 `YYYY-MM`。
- 金额必须大于 0。
- 收款方类型为“个人/员工”时，不要求供应商编码。
- 收款方类型为“供应商”时，优先按供应商名称匹配；匹配不到允许作为“公司”导入草稿，但需要醒目标记“未匹配供应商”。
- 项目/合同/阶段匹配失败时不写入正式计划，可进入导入预览错误列表。

## 9. 与飞书通知的关系

第一阶段只做系统内列表、计划维护、经营分析和导出，不默认飞书推送，也不产生审批任务。

后续可配置通知策略：

- 回款计划未维护提醒：每月第 5 个工作日提醒项目负责人。
- 本月回款计划临近未完成：月底前 5 天提醒项目负责人和经营管理。
- 加急付款计划提醒：提交后提醒财务资金计划人员。
- 计划付款日临近：计划付款日前 3 天提醒经办人和财务。

通知卡片只展示摘要，不展示完整银行账号、证件信息。

## 10. 开发分期建议

### 第一期：台账与计划

- 新增回款台账页面。
- 新增付款计划页面。

- 回款计划未维护提醒。
- 计划未完成提醒。
- 加急付款提醒。
- 计划付款日临近提醒。

## 11. 本次确认结论

1. 回款台账按“项目 + 收入合同”汇总，不按合同阶段拆多行。
2. 付款计划允许纯手工计划，不绑定项目/合同/阶段。
3. 个人收款方支持员工、外部个人和其他；系统只要求姓名、收款银行/账号、事由等业务必要信息，不强制证件字段。
4. 第一期先不做飞书提醒，只做页面、计划维护、经营分析和导出。
5. 回款计划、付款计划都不需要审批。

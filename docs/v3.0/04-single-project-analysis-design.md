# 单项目经营分析设计

 > 文档基线：v3.0.27 ｜ 日期：2026-09-02 ｜ 对应生产版本：v3.0.26 ｜ 状态：已同步，持续维护中
>
> 适用范围：项目详情页的单项目经营分析，不改变工时看板的工时口径。

## 1. 设计目标

项目负责人打开一个项目后，应该在一个页面回答四个问题：

1. 这个项目的成本由什么组成，人员成本和合同成本是否超出预算。
2. 收入合同、支出合同的每个阶段计划了多少，已经收付多少，还差多少。
3. 当前有哪些已逾期、即将到期或审批中的事项需要处理。
4. 距离计划结项还有多久，结项前是否能完成应收和应付，哪些款项会在结项后形成风险。

本页提供经营判断和下钻入口，不替代财务总账。未审批的收款单、付款单不计入已收、已付和项目实际经营金额。

## 2. 页面定位

沿用现有项目详情页，将“概况”升级为“项目经营分析”。不新增独立的重复菜单，项目列表点击项目后默认进入该页面。

```text
项目详情
├─ 经营分析（默认）
├─ 基本信息
├─ 人员与工时
├─ 预算
├─ 合同与资金
└─ 操作记录
```

“合同与资金”保留原始合同、阶段、收款单和付款单的维护能力；“经营分析”负责跨模块汇总、对比和预警，所有数字都可点击下钻到来源数据。

## 3. 页面结构

```text
┌─────────────────────────────────────────────────────────────┐
│ 返回项目列表  项目名称 / 编号 / 类型 / 状态       [编辑] [更多] │
│ 客户 · 负责人 · 项目周期                         结项倒计时       │
├─────────────────────────────────────────────────────────────┤
│ 收入合同 │ 支出合同 │ 总成本 │ 毛利 │ 未完成预警              │
├──────────────────────────────┬──────────────────────────────┤
│ 成本组成与预算执行             │ 结项资金风险                   │
│ 人员成本 / 合同成本 / 预算剩余  │ 距结项天数、结项前应收、应付     │
│ 成本趋势                       │ 逾期、即将到期、结项后风险       │
├──────────────────────────────┴──────────────────────────────┤
│ 合同阶段收付款分析                                             │
│ [收入合同] [支出合同]                                          │
│ 合同 | 阶段 | 计划日期 | 计划金额 | 已收/已付 | 未收/未付 | 状态 │
├─────────────────────────────────────────────────────────────┤
│ 风险与待处理事项                                               │
│ 严重 / 预警 / 提示，点击进入对应阶段或单据                      │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 顶部项目摘要

- 项目名称、项目编号、项目类型、项目状态、客户、负责人。
- 开始日期、计划结项日期。
- 结项倒计时：`计划结项日期 - 当前业务日期`。
- 快捷操作：编辑项目信息、发起付款、增加收款、填报工时，按权限和项目类型显示。
- 未设置计划结项日期时显示“未设置结项日期”，不虚构倒计时，并在风险区提示。

### 3.2 核心经营指标

指标采用紧凑横向指标栏，不使用大面积彩色卡片。数值按人民币元展示，百分比保留 1 位小数。

| 指标 | 展示内容 | 点击下钻 |
|---|---|---|
| 收入合同 | 生效收入合同金额 | 收入合同列表 |
| 支出合同 | 生效支出合同金额 | 支出合同列表 |
| 总成本 | 人员成本 + 已确认外部合同成本 | 成本组成 |
| 已收 / 应收 | 已确认收款 / 当前应收 | 收入阶段 |
| 已付 / 应付 | 已确认付款 / 当前应付 | 支出阶段 |
| 毛利 / 毛利率 | 已收 - 总成本 / 毛利 ÷ 已收 | 经营流水 |
| 预警事项 | 严重、预警、提示数量 | 风险列表 |

研发、课题、观摩项目默认以支出和成本为重点；实施项目同时展示收入侧和支出侧，不能隐藏支出合同、应付和已付。

## 4. 成本组成分析

### 4.1 成本分类

项目总成本拆分为两类：

```text
人员成本 = Σ（已审批工时天数 × 审批通过时的人员单天成本快照）
合同成本 = Σ（已审批通过且未冲销的付款单）
总成本 = 人员成本 + 合同成本
成本预算剩余 = max（成本预算 - 总成本，0）
```

收款不参与成本计算；未审批付款和草稿付款不参与成本计算。

### 4.2 人员成本使用率

按已确认的业务口径计算：

```text
加权平均单天成本
  = Σ（已审批工时天数 × 审批时人员单天成本）
    ÷ Σ（已审批工时天数）

人员成本预算基线
  = 项目人天预算 × 加权平均单天成本

人员成本使用率
  = 已发生人员成本 ÷ 人员成本预算基线 × 100%
```

边界规则：

- 人天预算为 0 或没有已审批工时时，人员成本使用率显示“暂无基准”，不能显示 0%。
- 人员成本快照优先使用工时审批通过时保存的单天成本，不受后来人员成本调整影响。
- 已发生人员成本由项目经营流水汇总，工时审批通过才生成流水。

### 4.3 成本区域展示

左侧展示三层信息：

1. **组成条**：人员成本、合同成本、总成本相对成本预算的占比。两种成本使用不同但克制的颜色，超预算时总条变为风险色。
2. **成本对比**：预算成本、人员成本、合同成本、总成本、预算剩余。
3. **月度趋势**：按业务月份显示人员成本、合同成本和总成本，支持点击月份查看对应工时和付款单。

同时显示：

- 人天预算、已发生人天、剩余人天、人天执行率。
- 成本预算、总成本、预算剩余、总成本使用率。
- 人员成本预算基线、人员成本使用率。

## 5. 合同阶段收付款分析

### 5.0 合同与阶段交互

- 合同列表只展示合同主信息；点击“查看阶段”仅打开阶段列表，不直接展开新增表单。
- 点击合同名称进入合同详情页，在详情页完整铺开展示合同信息和全部合同阶段。
- 只有点击“新增阶段”才打开阶段新增弹窗；阶段编辑使用独立编辑弹窗，避免新增表单与阶段列表混在一起造成误操作。
- 项目详情“合同与资金”中的收入合同和支出合同名称使用相同的合同详情入口。

### 5.1 收入合同和支出合同并列

页面采用两个明确的 TAB：`收入合同`、`支出合同`。实施项目默认两个 TAB 都显示；只有一侧存在数据时，另一侧仍保留并显示空状态和创建入口，避免用户误以为支出合同没有实现。

每个合同先显示汇总行，再展开阶段明细：

| 字段 | 收入合同 | 支出合同 |
|---|---|---|
| 合同金额 | 收入合同额 | 支出合同额 |
| 已确认金额 | 已收 | 已付 |
| 未结金额 | 应收 | 应付 |
| 完成率 | 已收 ÷ 合同金额 | 已付 ÷ 合同金额 |
| 最近风险 | 收款阶段逾期/临期 | 付款阶段逾期/临期 |

阶段明细字段：

| 字段 | 说明 |
|---|---|
| 阶段 | 阶段名称和顺序 |
| 计划日期 | 收款或付款计划日期 |
| 计划金额 | 阶段应收或应付原始金额 |
| 已收 / 已付 | 已审批且未冲销的实际金额 |
| 未收 / 未付 | `max(计划金额 - 已确认金额, 0)` |
| 结算率 | `已确认金额 ÷ 计划金额` |
| 状态 | 未到期、即将到期、已到期、部分完成、已完成、已逾期 |
| 风险 | 逾期、临期、结项后、未排期、待审批 |
| 操作 | 查看阶段、查看单据、新增收款/付款 |

阶段金额不允许手工录入“已收/已付”和“剩余”，统一从收付款单重新汇总。阶段计划金额合计与合同金额不一致时，在合同汇总行显示数据异常提示。

### 5.2 阶段状态优先级

状态按照以下优先级计算：

```text
已取消 > 已完成 > 部分完成 > 已逾期 > 即将到期 > 未到期
```

其中：

- 已完成：剩余金额小于等于 0。
- 已逾期：计划日期早于当前业务日期且仍有剩余金额。
- 即将到期：当前日期进入阶段的 `remind_days_before` 范围且仍有剩余金额。
- 待审批收付款单单独标记，不提前计入已收或已付。

## 6. 结项资金风险

### 6.1 结项窗口

根据计划结项日期计算：

```text
距离结项天数 = 计划结项日期 - 当前业务日期
```

窗口规则：

| 条件 | 页面状态 | 处理重点 |
|---|---|---|
| 未设置结项日期 | 未设置 | 提示项目负责人补充计划日期 |
| 大于 30 天 | 正常 | 展示常规阶段到期预警 |
| 8 至 30 天 | 结项临近 | 汇总结项日前计划收付款和剩余金额 |
| 0 至 7 天 | 即将结项 | 强调结项前未收、未付和待审批事项 |
| 小于 0 天 | 已超过计划结项 | 标记结项逾期，并显示全部未结事项 |

阈值只影响展示和提醒级别，不改变合同阶段本身的计划日期和金额。

### 6.2 结项前后金额划分

针对每个未完成阶段，按计划日期分组：

- **结项前待收 / 待付**：剩余金额大于 0，且计划日期不晚于计划结项日期。
- **结项后待收 / 待付**：剩余金额大于 0，且计划日期晚于计划结项日期。
- **未排期待收 / 待付**：剩余金额大于 0，但阶段没有计划日期。
- **待审批金额**：已提交但尚未审批的收付款金额，单独展示，不混入已收和已付。

右侧“结项资金风险”区域至少显示：

- 距离结项：天数和日期。
- 结项前待收金额、占收入合同未结金额比例。
- 结项前待付金额、占支出合同未结金额比例。
- 结项后待收、结项后待付、未排期金额。
- 待审批合同收款金额、待审批合同付款金额。
- 结项前资金闭合状态：正常、存在未结项、已逾期。

结项前收付款覆盖率：

```text
结项前收款覆盖率 = 结项前已收 ÷ 结项前计划应收金额
结项前付款覆盖率 = 结项前已付 ÷ 结项前计划应付金额
```

当结项前计划金额为 0 时显示“无结项前计划”，不显示 0%。

## 7. 预警中心

### 7.1 预警级别

| 级别 | 颜色语义 | 触发条件 | 默认动作 |
|---|---|---|---|
| 严重 | 红色 | 已逾期、结项日期已过仍有未收/未付、成本预算超支、阶段计划晚于结项日 | 项目负责人立即处理，并发送飞书提醒 |
| 预警 | 橙色 | 阶段进入提醒窗口、结项剩余 7 天内仍有未结项、人员成本或总成本达到预算 80% | 工作台和项目详情显示，按规则发送提醒 |
| 提示 | 蓝色 | 未设置结项日期、阶段未排期、存在待审批收付款 | 页面提示，不重复打扰 |

### 7.2 预警去重和文案

每条预警包含：项目、合同、阶段、预警类型、业务日期、金额、当前状态和处理入口。相同阶段、相同类型、相同业务日只生成一条提醒事件。

示例文案：

- `收入合同“设备验收款”已逾期 5 天，仍有 ¥80,000 未收`
- `项目距离计划结项还有 6 天，结项前仍有 ¥120,000 待收、¥45,000 待付`
- `支出阶段“现场服务费”计划日期晚于项目结项日 12 天`
- `项目总成本已使用成本预算的 86.4%，剩余 ¥18,000`
- `付款单 PAY-2026-0012 待出纳审批，金额 ¥30,000，暂不计入已付`

预警列表按严重级别、距到期天数、金额倒序排列。点击预警直接打开阶段或单据详情，不只跳到列表首页。

## 8. 数据口径

| 指标 | 计算方式 |
|---|---|
| 收入合同额 | 未作废生效收入合同金额合计 |
| 支出合同额 | 未作废生效支出合同金额合计 |
| 已收 | 已审批收款 - 已审批收款冲销 |
| 已付 | 已审批付款 - 已审批付款冲销 |
| 应收 | 核算日当天及之前的收入阶段计划金额 - 对应阶段已收，逐阶段取不小于 0 的剩余金额 |
| 应付 | 到期支出阶段计划金额 - 阶段已付 |
| 人员成本 | 项目已审批工时的人员成本流水合计 |
| 合同成本 | 已付，按已审批付款确认 |
| 总成本 | 人员成本 + 合同成本 |
| 毛利 | 已收 - 总成本 |
| 毛利率 | 已收大于 0 时，毛利 ÷ 已收 |
| 成本预算剩余 | max（成本预算 - 总成本，0） |
| 人天预算剩余 | max（人天预算 - 已审批人天，0） |

金额汇总必须可以由项目经营流水和合同阶段明细重新计算。所有金额使用数据库定点数，前端只负责格式化和展示。

## 9. 接口设计

新增单项目分析接口，避免前端同时请求多个列表后自行拼接口径：

```text
GET /api/v1/projects/{project_id}/analysis
```

可选参数：

- `as_of`：业务日期，默认当前日期，用于测试和历史回看。
- `include_trend`：是否返回月度趋势，默认 true。

返回结构：

```json
{
  "project": {},
  "kpis": {},
  "cost": {
    "personnel_cost": 0,
    "contract_cost": 0,
    "total_cost": 0,
    "budget_cost": 0,
    "remaining_cost": 0,
    "personnel_cost_budget_base": 0,
    "personnel_cost_usage_rate": null,
    "cost_usage_rate": null,
    "monthly_trend": []
  },
  "settlement": {
    "income_contracts": [],
    "expense_contracts": [],
    "pending_receipt_amount": 0,
    "pending_payment_amount": 0,
    "pending_approval_receipt_amount": 0,
    "pending_approval_payment_amount": 0
  },
  "closeout": {
    "planned_end_date": null,
    "days_to_close": null,
    "before_close_receivable": 0,
    "before_close_payable": 0,
```

接口必须复用项目数据范围权限。无权限访问项目时返回 403；项目不存在或已删除时返回 404；`as_of` 非法时返回 400。

## 10. 交互状态

- 加载：骨架结构保留顶部项目名称和模块标题，避免整页只显示“正在加载”。
- 空数据：没有合同、阶段或成本数据时，显示说明和对应的新增入口，不显示一堆 0。
- 部分数据：某一模块失败不阻塞其他模块，错误区域提供重试按钮。
- 权限不足：隐藏敏感金额和银行账号，但不破坏项目基本信息布局。
- 数据刷新：进入详情时加载一次；审批完成、收付款完成、工时审批完成返回项目详情时局部刷新分析接口。
- 业务日期：正式页面使用服务器业务日期，不能依赖用户设备时间。

## 11. 实施顺序

### P0

1. 项目分析接口和统一金额口径。
2. 核心指标、成本组成、预算剩余。
3. 收入/支出合同阶段明细和阶段状态。
4. 结项倒计时、结项前后应收应付。
5. 逾期、临期、结项风险预警。
6. 从指标和预警下钻到合同阶段、收付款单、工时明细。

### P1

1. 月度成本趋势和收付款趋势。
2. 项目经营流水时间线。
3. 预警处理状态、负责人确认和处理记录。
4. 项目分析导出 PDF/Excel。

## 12. 验收标准

1. 实施项目同时展示收入合同和支出合同，研发项目至少展示支出合同和成本侧。
2. 人员成本、合同成本、总成本和成本预算剩余能够逐笔下钻并与经营流水对账。
3. 收付款阶段支持未到期、临期、逾期、部分完成和已完成状态。
4. 收付款单未审批时不会进入已收、已付、应收核销、应付核销和毛利计算。
5. 设置计划结项日期后，系统正确拆分结项前、结项后和未排期的应收应付金额。
6. 距结项 7 天、结项已过期、阶段计划晚于结项日等场景会产生对应预警。
7. 用户点击预警、合同阶段、已收/已付或成本数字时，能进入对应明细并保留项目上下文。
8. 无项目看板或财务权限的用户不能通过接口获取单项目经营金额。
9. 项目无预算、无结项日期、无合同、无阶段时，页面分别给出明确空状态，不用 0 值制造错误结论。

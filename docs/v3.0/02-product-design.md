# 综合项目管理系统产品与交互设计

> 文档基线：v3.0.44 ｜ 日期：2026-09-06 ｜ 对应生产版本：v3.0.43 ｜ 状态：方案已确认，高保真原型已完成；未开发

## 1. 设计原则

1. 首页先展示需要处理的事情，再展示汇总数字。
2. 工时与项目经营分开组织，避免把成本、预算重新塞回工时看板。
3. 项目列表只负责定位项目，经营数据放到详情和项目看板。
4. 合同阶段是应收应付的来源，合同收付款单是实际资金确认的来源。
5. 敏感账户默认脱敏，审批后数据只读，错误通过冲销修正。
6. 桌面端服务于高频管理操作；员工工时和审批继续保证移动端可用。

## 2. 全局导航

桌面端左侧导航使用四个一级分组。一级分组可展开和收起，当前分组保持展开。

```text
工作台

工时管理
  我的工时
  工时审批（显示待办数）
  工时看板
  工时台账（按权限显示）

项目管理
  项目管理
  项目合同
  合同收款（显示待审批数）
  合同付款（显示待审批数）
  项目看板
  供应商管理
  客户管理

系统管理
  人员成本
  集成与通知
  管理员管理
  基础配置
```

移动端底部只保留“工作台、我的工时、工时审批、项目、更多”。复杂的合同、看板和系统配置页面允许在移动端查看，但新增和编辑优先引导使用桌面端。

## 3. 工作台设计

### 3.1 页面结构

```text
┌─────────────────────────────────────────────────────────────┐
│ 问候语 / 当前日期                        [填报工时] [更多操作] │
├─────────────────────────────────────────────────────────────┤
│ 我的项目（项目负责人或授权用户显示）                           │
│ [负责项目] [待审工时] [7天应收] [7天应付] [逾期事项]           │
│                                                             │
│ 项目经营概况表                                                │
│ 项目 | 类型 | 预算执行 | 人员成本 | 已付/应付 | 已收/应收 | 预警 │
│                                                             │
│ [发起合同付款] [增加收款] [工时审批]              项目提醒列表     │
├─────────────────────────────────────────────────────────────┤
│ 我的工时                                                     │
│ [本月工时审批数] [待审批] [已驳回] [草稿]                      │
│ 最近工时 / 审批状态时间线                         [填报工时]   │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 项目负责人区域

#### 顶部指标

- 负责项目：点击进入项目管理并自动筛选当前负责人。
- 待审工时：点击进入工时审批待办 TAB。
- 7 天内应收：点击进入项目合同收入合同 TAB，并筛选即将到期。
- 7 天内应付：点击进入项目合同支出合同 TAB，并筛选即将到期。
- 逾期事项：点击打开应收、应付和预算预警抽屉。

#### 项目经营概况

默认展示最近活跃或风险最高的 5 个负责项目，可切换“全部负责项目”。

研发、课题、观摩项目行：

- 项目名称、状态。
- 人天预算执行进度。
- 成本预算执行进度。
- 人员成本。
- 已付 / 应付。
- 风险标签。

实施项目同时存在收入侧和支出侧业务。项目行在研发类成本指标基础上额外展示：

- 已收 / 应收。
- 收款进度。
- 毛利。

实施项目原有的人员成本、已付 / 应付和付款进度必须继续展示，不能因为增加收入侧指标而隐藏支出侧信息。

数字不使用整张彩色卡片。正常状态使用中性色，接近预算使用橙色，超预算和逾期使用红色。

#### 快捷操作

点击“发起合同付款”后先选择项目，再按项目过滤可付款的支出合同和阶段。点击“增加收款”使用相同流程筛选收入合同。实施项目同时显示两个入口；没有对应合同阶段时不允许直接创建无来源单据。

### 3.3 员工区域

- 本月总计工时审批数显示当前自然月已通过和已锁定的工时单据笔数。
- 待审批、已驳回和草稿均可点击进入对应筛选结果。
- 最近工时展示项目、日期、天数、工作摘要和最新状态。
- “填报工时”为最明显的主按钮。

如果当前用户不是项目负责人，项目负责人区域完全隐藏，员工区域上移，不显示空卡片。

### 3.4 工作台状态

- 加载：项目区和员工区分别使用骨架，不互相阻塞。
- 空项目：显示“当前没有负责的项目”，不显示经营指标。
- 部分失败：合同提醒失败不影响员工工时展示，并提供局部重试。
- 权限变化：用户权限被收回后，下一次请求立即隐藏敏感项目和金额。

## 4. 工时管理设计

### 4.1 我的工时

保留现有交互。筛选区域包含日期、项目类型、项目、状态和关键字。项目必须先按类型过滤。移动端使用卡片列表，桌面端使用紧凑表格。

### 4.2 工时审批

保留“待我审批 / 已审批”TAB。工作台进入时自动定位待审批 TAB；飞书卡片链接携带审批任务 ID，登录后直接打开详情。

### 4.3 工时看板

#### 保留指标

- 已审批工时天数。
- 填报人数。
- 涉及项目数。
- 待审批数量和天数。
- 审批通过率。

#### 保留图表

- 工时趋势折线图。
- 一级部门工时柱状图。
- 项目工时排行。
- 人员工时排行。
- 项目类型分布。
- 工作阶段分布。
- 审批状态分布。

#### 移除内容

- 成本预算、实际人工成本和成本使用率。
- 项目人天预算对比。
- 毛利和收付款信息。
- 缺少人员成本配置的提醒。

工时明细导出继续与当前筛选条件完全一致。

### 4.4 工时台账

沿用现有后台工时管理，筛选区统一为日期、部门树、人员、项目、状态和关键字。分页支持 10、20、50 和自定义条数。

## 5. 项目管理设计

### 5.1 项目列表

#### 筛选

- 项目类型。
- 项目状态。
- 所属部门树。
- 项目负责人。
- 客户。
- 项目名称或编号。

筛选组居中、紧凑排列，部门使用树形下拉。拥有全部项目权限的用户增加“数据范围：我的项目 / 全部项目”分段控件。

#### 列表字段

| 字段 | 展示方式 |
|---|---|
| 项目 | 名称为主，编号为辅 |
| 状态 | 状态标签 |
| 类型 | 类型标签 |
| 负责人 | 姓名 |
| 所属部门 | 组织架构路径，过长省略 |
| 客户 | 客户简称或名称 |
| 工时填报 | 可填报 / 不可填报 |
| 操作 | 查看、编辑、更多 |

列表不展示预算和经营金额，不出现横向滚动条。点击整行进入项目查看页，编辑使用独立详情页，不再使用承载全部字段的大弹窗。

### 5.2 项目详情

页面头部固定展示项目名称、编号、类型、状态、负责人和风险标签。右侧提供“编辑主信息、发起合同付款、增加收款、填报工时”。操作按权限与项目类型显示。

TAB 设计：

#### 概况

- 人天预算、已发生人天、剩余人天和执行率。
- 成本预算、人员成本、外部成本、总成本和执行率。
- 实施项目同时显示收入、应收、已收、毛利和毛利率，以及外部成本、应付、已付和付款进度。
- 研发类项目默认隐藏收入区。
- 即将到期、逾期和超预算提醒。

#### 基本信息

编辑名称、编号、状态、类型、负责人、部门、客户、日期、说明和是否允许工时填报。

#### 人员与工时

编辑工时审批人和上级领导；查看项目工时趋势和明细。已发生人天只读。

#### 预算

编辑人天预算、成本预算和费用预算。保存预算变更时必须填写变更原因，保留变更前后值。

#### 合同与资金

收入合同、支出合同、合同收款单和合同付款单四个子 TAB。实施项目完整显示四个子 TAB；支持从项目详情创建，项目自动带入且不可切换。

#### 操作记录

按时间倒序展示项目、预算、合同、收付款和权限相关审计事件。

## 6. 项目合同设计

### 6.1 合同列表

页面使用“收入合同 / 支出合同”TAB。筛选包含项目、合同状态、客户或供应商、到期状态、签订日期和关键字。

列表字段：合同编号、合同名称、项目、客户/供应商、合同金额、阶段进度、已收/已付、待收/待付、最近到期日、状态和操作。

### 6.2 合同编辑页

分为三个区域：

1. 合同基本信息。
2. 收款或付款阶段。
3. 附件与备注。

阶段使用可增删的紧凑表格：

| 序号 | 阶段名称 | 计划金额 | 计划日期 | 提前提醒 | 状态 | 操作 |
|---|---|---:|---|---|---|---|

页面底部实时展示合同金额、阶段金额合计和差额。差额不为 0 时可以保存草稿，但不能将合同置为生效。

### 6.3 合同详情

顶部展示合同金额和完成进度。阶段时间线清晰区分未到期、即将到期、到期、部分完成、已完成和逾期。点击阶段可打开对应收付款明细。

## 7. 合同收款设计

### 7.1 列表

使用“待我审批 / 全部单据”TAB。出纳角色默认进入待我审批，项目负责人默认看到负责项目的全部单据。

筛选包含状态、项目、合同、客户、收款日期、发起人和关键字。

### 7.2 新增合同收款单

填写顺序：

1. 选择项目。
2. 选择收入合同。
3. 选择有剩余应收的阶段。
4. 系统显示阶段计划金额、已收和剩余应收。
5. 填写本次金额、收款日期和账户信息。
6. 上传收款凭证。
7. 保存草稿或提交出纳审批。

核心字段：

- 合同收款单号，系统生成。
- 项目、收入合同、合同阶段。
- 客户和付款户名。
- 付款开户行、付款账号。
- 公司收款账户。
- 收款日期、收款金额、银行流水号。
- 收款方式、凭证附件、备注。

本次金额不能大于阶段剩余应收。允许多笔部分收款。

### 7.3 合同收款审批

审批详情同时展示合同、阶段、金额、账户和凭证。出纳可以通过或驳回，驳回原因必填。通过按钮必须二次确认，确认文案明确说明“通过后将计入项目收入并核减应收”。

## 8. 合同付款设计

### 8.1 新增合同付款单

填写顺序与合同收款单一致，但选择支出合同、付款阶段和供应商。

核心字段：

- 合同付款单号，系统生成。
- 项目、支出合同、合同阶段。
- 供应商。
- 收款户名、开户行、银行账号。
- 公司付款账户。
- 付款日期、付款金额、银行流水号。
- 付款方式、付款用途、凭证附件、备注。

供应商默认账户自动带出，修改只影响本单快照。页面明显提示账号后四位，并在提交前要求再次核对。

### 8.2 合同付款审批

通过前二次确认文案为“通过后将计入项目外部成本、增加已付并核减应付”。驳回后发起人可编辑重提，旧审批记录保留。

## 9. 供应商与客户设计

### 9.1 供应商核心字段

| 分类 | 字段 |
|---|---|
| 基本信息 | 全称、简称、统一社会信用代码、状态；供应商编码系统自动生成 |
| 证照 | 营业执照附件、证照有效期 |
| 地址 | 注册地址、办公地址 |
| 联系人 | 姓名、手机、电话、邮箱 |
| 银行账户 | 户名、开户银行、支行、银行账号、是否默认 |
| 其他 | 备注、创建人、更新时间 |

同一供应商允许多个银行账户，但只有一个默认账户。银行账号默认脱敏显示。

### 9.2 客户核心字段

| 分类 | 字段 |
|---|---|
| 基本信息 | 全称、简称、统一社会信用代码、状态；客户编码系统自动生成 |
| 证照 | 营业执照附件、证照有效期 |
| 地址 | 注册地址、办公地址 |
| 联系人 | 姓名、手机、电话、邮箱 |
| 往来信息 | 开票抬头、纳税人识别号、开户行、账号、开票地址和电话 |
| 其他 | 备注、创建人、更新时间 |

客户和供应商的统一社会信用代码在启用数据中不得重复。历史合同引用快照，不随主数据修改而改变。

## 10. 项目看板设计

### 10.1 筛选区

- 数据范围：我的项目 / 全部项目。
- 项目类型、项目状态、所属部门、项目负责人、客户、项目。
- 统计截止日期。
- 查询和导出。

没有“查看全部项目”权限时不展示数据范围切换，也不接受接口传入全量范围。

### 10.2 内容顺序

1. 经营 KPI：收入、总成本、应收、应付、已收、已付、毛利、毛利率。
2. 风险摘要：逾期应收、逾期应付、超人天预算、超成本预算。
3. 收支趋势：按月展示已收、已付和人员成本。
4. 项目毛利排行。
5. 应收应付账龄。
6. 预算执行散点或条形对比。
7. 项目经营明细表，可下钻。

研发类项目在单项目视图中默认隐藏收入、应收和已收；实施项目在单项目视图中同时展示收入与支出两侧；全部项目汇总时显示实施项目贡献的收入和支出。

## 11. 管理员与基础配置设计

### 11.1 管理员管理

添加管理员时按模块勾选权限，并额外配置数据范围：

- 仅本人负责项目。
- 指定部门及下级部门。
- 全部项目。

出纳审批为独立权限。至少保留一名系统管理员和一名出纳，不能移除最后一人。

### 11.2 基础配置

基础配置按分类 TAB 展示。选项支持新增、编辑、排序、启用和停用；已经被业务数据引用的选项不能删除。

会驱动状态机的固定编码只允许改显示名称，不允许改变编码和状态顺序。

## 12. 通知设计

飞书卡片分为四类：

- 工时审批待办。
- 合同收款审批待办。
- 合同付款审批待办。
- 合同阶段到期/逾期和预算预警。

卡片只展示必要摘要，银行账号只显示后四位。按钮通过飞书 AppLink 在内置浏览器打开对应详情。审批结果卡片发送给发起人和项目负责人。

## 13. 错误与边界状态

- 合同阶段余额不足：禁止提交超额收付款。
- 同一单据重复提交：返回原审批任务，不重复生成经营流水。
- 审批时余额已变化：提示数据已更新，要求重新加载。
- 出纳权限已收回：不能继续处理待审批任务，由系统管理员重新分配。
- 飞书通知失败：单据仍保持待审批，页面显示失败原因并允许重试。
- 附件上传失败：不提交审批，保留表单数据。
- 已审批单据发现错误：必须发起冲销，不能直接编辑。
- 供应商或客户停用：历史数据可查，新合同不可选择。

## 14. 原型确认顺序

开发前建议按以下顺序确认高保真原型：

1. 四大模块导航和工作台。
2. 项目列表、项目详情与预算 TAB。
3. 合同列表、合同编辑和阶段表格。
4. 合同收款单、合同付款单及出纳审批详情。
5. 项目看板。
6. 供应商、客户和权限配置。

每组原型确认后冻结页面字段和操作，不在编码阶段重新讨论主流程。

## 15. 当前基线同步说明

当前生产 UI 已在原有浅色业务系统和青绿色主色基础上完成四大模块、工作台双布局、项目详情六页签、合同详情、合同收付款审批详情、通知中心和管理员配置页面。项目管理列表保持桌面端信息平铺且无页面级横向滚动；部门筛选使用组织树并包含下级部门；合同阶段改为“先查看列表、再点击新增”；新建合同和合同收付款单均可预选附件。

移动端只保证工作台、工时填报、工时审批、通知和详情等高频路径可用；项目管理、合同管理和经营看板以桌面端为主要使用场景。当前页面具体状态、空态、错误态和操作反馈以 [82-current-baseline-v3.0.91.md](82-current-baseline-v3.0.91.md) 为准；v3.0.70 用户手册为最近成册版，但已滞后于当前生产功能。

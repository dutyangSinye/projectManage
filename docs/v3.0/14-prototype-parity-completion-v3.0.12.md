# 原型差异补齐实施说明

- 版本：v3.0.12
- 日期：2026-09-01
- 状态：已完成并部署验证（v3.0.13）
- 适用系统：综合项目管理系统

## 1. 背景

上一版将原型差异误判为全部完成。本说明以生产代码和原型逐项复核结果为准，补齐仍停留在摘要、静态说明或半成品入口的功能，不改变已经确认的业务口径：

- 已审批工时、已审批收付款才进入经营事实；
- 应收只统计已到期收入阶段的未收金额，应付只统计已到期支出阶段的未付金额；
- 飞书用于组织同步、应用消息通知和内置浏览器入口，本地系统保存业务审批状态，不依赖回调；
- 不替换现有 Docker 数据卷。

## 3. 数据和接口约定

### 3.1 组织同步

`OrgSyncLog` 增加 `added_user_count`、`updated_user_count`、`added_department_count`、`updated_department_count`、`duration_ms`。`GET /api/v1/integrations/overview` 返回：

- `summary.today_sent_count`：自然日发送成功数量；
- `summary.retry_count`：失败待重试数量；
- `sync_logs`：完整同步记录；
- `policies`：通知策略配置。

### 3.2 通知策略

策略按 `notification_type` 存储，字段包括 `enabled`、`send_channel`、`remind_days_before`。初始业务类型：工时审批、合同收付款审批结果、合同阶段临期/到期/逾期、成本预算、人天预算、待审批合同收款单、待审批合同付款单。未配置时使用现有发送行为作为默认值。

### 3.3 项目看板

`GET /api/v1/projects/board` 在现有项目行之外返回：

- `trend`：按月合同收入、合同支出、已收、已付；
- `aging.receivable`、`aging.payable`：未到期、0-30 天、31-60 天、61-90 天、90 天以上；
- `warning_items`：预警类型、项目、来源对象和金额。

账龄以查询日为基准，未到期阶段不计入应收/应付；已到期未结算按逾期天数分桶。

### 3.4 详情数据

收付款详情增加阶段计划金额、阶段已结算金额、阶段剩余金额、阶段结算率、申请人姓名和审批人姓名；项目审计详情增加对象显示名称和事件描述。兼容旧数据时字段返回空值，不阻塞历史记录查看。

## 4. 页面交互

- 集成与通知页面：概况卡片 → 同步时间线/通知策略 → 通知中心；通知行点击打开详情，失败行提供“重新发送”。
- 项目详情：六个页签保持平铺；经营分析预警、合同阶段和待审批金额均可下钻到合同、阶段或收付款详情。
- 项目看板：指标 → 趋势/毛利/账龄图表 → 项目明细表；表格项目名称和图表数据点进入项目详情。
- 合同详情：主信息、结算概况、阶段列表和附件按从业务主线到辅助资料的顺序展示；阶段新增单独弹窗。
- 收付款详情：单据上下文、阶段余额、审批时间线、审批操作分区展示；审批操作先二次确认。

所有页面补齐加载、空数据、接口错误、成功反馈，桌面端保持表格对齐，移动端详情纵向堆叠且不产生横向溢出。

## 5. 实施顺序

1. 后端模型增量字段、响应模型和统一查询接口。
2. 通知策略与组织同步统计入库。
3. 项目看板趋势、账龄和下钻数据。
4. 项目/合同/收付款详情字段与页面闭环。
5. 前端页面状态、筛选、详情弹窗和审批确认。
6. 后端测试、前端构建、API 冒烟、桌面及 390×844 回归、打包发布。

## 6. 验收重点

- 真实飞书 app 模式下集成页面仍受管理员权限保护；
- 通知发送失败只产生待重试记录，不回滚已完成审批；
- 合同收付款审批通过后仍保持幂等入账和申请人通知；
- 客户/供应商名称使用实时主数据名称，历史单据保留业务快照；
- 预算、应收、应付、毛利计算与既有口径一致；
- 旧数据无需人工迁移即可读取新字段。

## 7. 本轮闭环修订（2026-09-01）

上一轮实现已补齐后端数据基础和主要页面入口，但以下项目仍需从“有接口/有入口”闭环到“用户可操作、结果可验证”：

| 闭环项 | 本轮要求 | 验收口径 |
| --- | --- | --- |
| 通知策略实际生效 | `send_channel`、启用状态和提前天数统一经过通知服务判断，并覆盖工时、收付款、合同阶段、预算预警 | 关闭策略后不产生发送尝试；启用策略按配置渠道发送并留下记录 |
| 项目详情下钻 | 经营分析、预算、合同资金、预警中的项目/合同/阶段/单据可打开对应详情 | 至少可以从项目详情进入合同详情、阶段上下文和收付款单据详情 |
| 操作记录可读性 | 审计记录补齐事件描述、对象、操作者、时间和结果 | 时间线不再只显示事件编码，历史记录兼容展示 |
| 收付款详情闭环 | 详情直接展示项目、合同、阶段和往来单位上下文，并支持从详情进入合同 | 收款、付款均能看到审批时间线、阶段余额和关联合同 |
| 集成通知中心 | 同步时间线、通知策略、通知记录、失败原因和重试统一在页面呈现 | 桌面端信息对齐，390×844 不出现横向溢出 |

本轮关联回归范围：登录与管理员菜单权限、组织同步、工时审批通知、合同收付款审批入账、项目预算/应收/应付/毛利口径、合同阶段新增编辑、客户供应商实时名称、项目看板筛选及图表。任何一项冒烟失败，均不得打包发布。

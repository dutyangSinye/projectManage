# 合同付款动态审批闭环修复说明

- 版本：v3.0.46
- 日期：2026-09-07
- 状态：已发布
- 上游设计：`41-project-expense-workflow-design-v3.0.44.md`

## 1. 缺口

v3.0.45 已上线项目费用和动态审批基础设施，但合同付款单仍调用旧的单级出纳审批，与已确认的七级付款流程不一致。该缺口影响付款提交、节点通知、审批详情、权限和待审批金额统计。

## 2. 修复范围

1. `payments` 增加当前流程实例和单据版本字段，旧数据默认不绑定流程实例。
2. 新付款单先保存草稿，附件上传完成后再提交七级审批，避免审批人先收到无附件单据。
3. 付款流程固定使用已发布 `PROJECT_PAYMENT` 模板：项目审批、经营审批、上级领导、经营副总、会计审核、总经理审批、出纳支付。
4. 自审转上级、相邻重复审批人自动通过、岗位或签、出纳不自动通过沿用项目费用规则。
5. 每个新节点的候选人收到飞书卡片，卡片直达付款详情；当前任务人可查看并处理，不依赖项目列表数据范围。
6. 最后出纳节点通过后才写入 `PAYMENT` 项目资金/合同成本流水、更新阶段结算和付款单 `APPROVED` 状态；中间节点不记账。
7. 付款详情展示完整审批路径、当前节点和审批记录；列表“待我审批”只显示分配给当前用户的付款任务。
8. 历史没有流程实例的 `PENDING` 付款单保留旧出纳审批入口，已确认、已驳回和已冲销数据不重算。
9. 同一合同阶段的已确认、审批中及历史待审付款共同占用提交额度，防止多张待审批合同付款合计超过阶段金额；草稿不占用额度。
10. 付款被驳回或最终确认后的通知重试更新原通知记录，并从流程日志恢复实际处理人姓名。
11. 飞书卡片登录后继续加载付款详情和附件，不要求审批任务人拥有付款管理菜单权限。

## 3. 关联回归

- 付款草稿、附件上传、编辑、删除、重新提交、驳回、审批、冲销。
- 支出合同阶段剩余额度、项目合同成本、已付、应付和毛利。
- 项目费用五级/七级流程，确保通用工作流调整不造成回归。
- 收款单继续使用原出纳审批，不改变状态和统计口径。
- 飞书通知幂等、直达参数、未授权访问和任务越权。
- 旧库迁移幂等、用户/项目/角色和历史付款数据保留。

## 4. 准出标准

- 自动化测试覆盖合同付款完整七级流程，并验证只有出纳末节点写入一次付款流水。
- 前端生产构建通过，付款列表、详情和移动端无横向溢出。
- 生产部署后版本、数据库字段、流程路由、容器和健康检查通过。

# 综合项目管理系统 v3.0.29：首次飞书管理员与旧环境数据导入

- 版本：v3.0.29
- 日期：2026-09-05
- 状态：已确认，进入实现

## 1. 需求

1. 首次接入飞书并成功登录的用户，自动成为系统首位管理员。
2. 首位管理员只初始化一次；后续用户登录不能覆盖或替换首位管理员。
3. 将旧环境的有效项目导入新服务器；本次不导入客户、供应商、合同、合同阶段和合同附件。
4. 新服务器当前的飞书组织架构不被覆盖；项目主数据与组织人员关系在导入后保持一致。

## 2. 方案

### 首次管理员

- 在飞书 OAuth 换取成功、且本地用户已同步后执行初始化。
- 使用 `config_options` 的 `system_internal/FIRST_FEISHU_ADMIN_USER_ID` 作为持久化标记。
- 已配置的 `SYSTEM_ADMIN_USER_IDS` 优先保留，兼容现有部署；没有环境管理员且没有初始化标记时，写入当前用户本地 ID。
- 系统管理员判断统一合并环境配置与持久化标记，权限范围仍为全部菜单和全部数据。
- 初始化写入使用唯一键和事务，重复登录不会覆盖首位管理员。

### 旧数据导入

- 数据源使用旧环境清理前的 SQLite 备份，导入前备份新服务器数据库。
- 本次只导入项目主数据，不导入客户、供应商、合同、合同阶段、合同附件文件及元数据。
- 项目客户只保留旧记录中的 `customer_name` 快照，`customer_id` 置空，待后续客户主数据导入后再重新挂接。
- 已存在同项目编码的记录时更新业务字段，不重复创建。
- 旧项目中状态为 `DELETED` 的软删除记录不重新展示；有效项目按项目编码合并，避免历史删除项目被重新启用。
- 不导入旧用户、部门、工时、工时审批、通知、提醒和审计日志；人员字段沿用新服务器当前飞书组织架构。
- 旧项目的负责人、审批人、上级领导按飞书用户标识映射到新服务器用户；无法映射时保留姓名快照并置空本地用户 ID。
- 导入在事务中执行；附件文件先复制到临时目录，数据库提交后再切换到正式附件目录。

## 3. 受影响模块

- 后端 OAuth 登录与系统管理员判定。
- 后端数据库配置标记和项目主数据。
- NAS 新服务器数据库。
- 不修改旧服务器数据，仅读取旧备份作为导入源。

## 4. 验收标准

- 空管理员配置时，第一个成功飞书登录用户返回 `is_system_admin=true`，刷新/重启后仍为系统管理员。
- 第二个及后续用户登录不会改变首位管理员。
- 已配置环境管理员时，不额外生成首位管理员标记。
- 导入后有效项目数量与源备份一致或有明确的已存在合并记录；软删除项目不重新展示。
- 项目与组织人员关系可正常查询；外键检查无异常。
- 新服务器 `/health` 返回 200，首页和飞书登录接口正常。

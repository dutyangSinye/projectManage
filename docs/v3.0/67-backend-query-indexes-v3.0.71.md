# v3.0.71 后端查询索引优化说明

日期：2026-09-14  
状态：已实现，待发布生产

## 背景

前端大包拆分完成后，后端仍缺少针对核心业务查询的显式索引。当前系统多数页面是读多写少，尤其项目看板、工时台账、审批列表、合同收付款和费用复核会频繁按项目、状态、日期、审批人等字段组合查询。

本次只做低风险后端性能优化，不改变业务流程、审批口径、数据结构含义和接口返回字段。

## 优化范围

新增启动迁移索引，覆盖以下高频路径：

- 项目列表、项目看板：项目状态、负责人、部门、项目类型。
- 工时台账与工时看板：填报人、项目、状态、开始日期。
- 工时审批：审批人、审批状态、提交时间、工时审批版本。
- 合同与合同阶段：项目、合同类型、状态、阶段计划日期。
- 合同收款与合同付款：项目、合同、阶段、状态、业务日期。
- 项目费用与费用复核：项目、申请人、费用类型、状态、发生日期。
- 人工成本结转/其他成本单：项目、单据类型、状态、核算月份。
- 项目流水：项目、流水类型、来源单据、预算项。
- 通知中心：通知状态、接收人、来源业务对象。
- 动态审批任务：审批人、状态、审批实例、节点顺序。

## 实现方式

- 在 `backend/app/main.py` 中新增 `QUERY_INDEX_SPECS`，统一维护索引清单。
- 新增 `ensure_query_indexes(connection)`，在 `upgrade_schema()` 中执行。
- 对既有 SQLite 生产库使用 `CREATE INDEX IF NOT EXISTS` 幂等补齐索引。
- 对新建库，启动时同样通过 `upgrade_schema()` 创建索引。
- 如果表或列不存在，会自动跳过对应索引，避免阻断历史库升级。

## 验证

- 后端测试：`84 passed`。
- 新增回归：`test_query_indexes_are_created_by_schema_upgrade`，验证关键表索引已创建。
- 前端构建：`pnpm --dir frontend build` 通过。

## 风险与注意

- 索引会略微增加写入时的维护成本，但当前系统写入量远低于查询量，收益大于成本。
- 首次部署到已有生产库时，启动阶段会创建索引；数据量越大，首次启动耗时可能略有增加。
- 本次不引入缓存、不改 SQL 结果、不改接口契约。

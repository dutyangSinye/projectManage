# v3.0.95 工时批量审批与工作台工时日历

日期：2026-10-09  
状态：已实现  

## 1. 背景

工时审批逐条处理效率较低；员工在工作台缺少直观的月度填报状态提醒，尤其是国家法定假日和调休规则引入后，需要在首页直接展示“已填、漏填、今日待填、非工作日”。

## 2. 功能范围

### 2.1 工时审批批量处理

- 在 `工时审批 / 待我审批` 增加勾选框、全选、清空选择。
- 支持批量通过。
- 支持批量驳回，驳回时必须输入统一原因。
- 批量处理逐条复用单条审批逻辑，保留：
  - 项目类二级审批流转；
  - 非项目类一级审批；
  - 审批版本校验；
  - 审批记录；
  - 下一审批人飞书通知。
- 单条失败不影响整批其他记录，返回成功/失败数量和失败原因。

### 2.2 工作台工时日历

- 工作台顶部新增“本月工时日历”。
- 日期颜色规则：
  - 已填报/已审批：绿色；
  - 已过但未填报：红色；
  - 今日未填：琥珀色；
  - 审批中：琥珀色；
  - 草稿：浅琥珀色；
  - 已驳回：红色；
  - 非工作日/法定假日：灰色。
- 日历按后台国家法定工作日历判断工作日：
  - 调休工作日计入应填；
  - 法定假日不计入应填；
  - 未维护的日期回退为周一至周五。
- 点击日期：
  - 有工时：打开该条工时，草稿/驳回进入编辑，其他状态进入详情；
  - 无工时：进入新增工时页，并默认填入填报日期、开始日期、结束日期；
  - 非工作日：先提示确认是否继续填报。

## 3. 接口设计

### 3.1 工时日历

`GET /api/v1/worklogs/calendar?month=YYYY-MM`

返回：

- `summary.required_workdays`：本月应填工作日；
- `summary.filled_days`：已填报日期数；
- `summary.missing_days`：已过但未填报日期数；
- `summary.today_missing`：今日未填标记；
- `summary.pending_count`：审批中记录数；
- `summary.rejected_count`：驳回记录数；
- `summary.draft_count`：草稿记录数；
- `days[]`：每天的工作日、状态、关联工时 ID、节假日名称。

### 3.2 批量审批

`POST /api/v1/approvals/batch-approve`

```json
{
  "task_ids": [1, 2, 3],
  "comment": ""
}
```

`POST /api/v1/approvals/batch-reject`

```json
{
  "task_ids": [1, 2, 3],
  "reason": "填写不完整"
}
```

返回：

```json
{
  "success_count": 2,
  "failed_count": 1,
  "results": [
    { "task_id": 1, "success": true, "worklog_id": 10, "status": "APPROVED" },
    { "task_id": 2, "success": false, "message": "VERSION_CONFLICT" }
  ]
}
```

# 综合项目管理系统产品需求文档

> 文档基线：v3.0.44 ｜ 日期：2026-09-06 ｜ 对应生产版本：v3.0.43 ｜ 状态：方案已确认，高保真原型已完成；未开发

## 1. 摘要

v3.0 将现有工时系统升级为“工时 + 项目经营”一体化系统，统一分为工作台、工时管理、项目管理、系统管理四大部分。系统继续使用飞书组织架构、飞书免登和飞书应用消息，同时新增合同、收款、付款、往来单位、项目经营看板和到期提醒能力。

本版本的核心目标不是替代财务总账，而是让项目负责人随时看清项目预算、工时、人员成本、应收、应付、已收、已付和毛利，并让每一笔项目收付款都有合同阶段、审批记录和审计轨迹可追溯。

## 2. 联系人

| 角色 | 人员 | 职责 | 备注 |
|---|---|---|---|
| 业务负责人 | 待指定 | 确认范围、业务规则和验收结果 | PRD 确认人 |
| 系统管理员 | 当前系统管理员 | 配置菜单权限、基础数据、飞书集成 | 不在代码中写死人员姓名 |
| 出纳角色首位人员 | 贺茂维 | 审批合同收款单和合同付款单 | 通过角色配置，不硬编码 |
| 项目负责人 | 飞书组织用户 | 管理负责项目、合同、提醒和经营数据 | 只能访问授权项目 |
| 工时审批人 | 项目配置人员 | 审批项目工时 | 沿用现有本地审批流程 |

## 3. 背景

### 3.1 当前情况

现有 v2.0 已经具备以下基础：

- 飞书组织架构同步和飞书免登。
- 单条工时填报、本地审批和飞书卡片提醒。
- 项目基础信息、项目审批链、人天预算和成本预算。
- 工时管理、人员单天成本、工时看板和模块权限。
- NAS Docker 部署、健康检查、备份和回滚能力。

当前项目数据、工时数据和成本预算已进入系统，但合同、应收应付、实际收付款和项目经营结果仍在线下维护，项目负责人无法在同一个页面判断项目的经营状态和近期风险。

### 3.2 为什么现在做

- 项目预算、人天和人员成本已经具备，继续补齐合同与资金台账后才能形成完整项目经营视图。
- 研发项目和实施项目的经营关注点不同，需要按项目类型展示不同指标。
- 到期应收、应付和审批待办依赖人工记忆，存在遗漏风险。
- 当前导航逐步增加，继续平铺菜单会降低使用效率，需要先完成信息架构重组。

### 3.3 产品边界

本系统是项目经营管理台账，不是会计总账、网银系统或发票系统。合同收付款审批通过仅确认项目经营数据，不直接发起银行转账，也不生成会计凭证。

## 4. 目标

### 4.1 业务目标

1. 项目负责人进入首页即可看到自己负责项目的预算、工时、成本和资金风险。
2. 合同阶段、应收应付、收付款和项目数据建立完整关联。
3. 收付款经过出纳角色审批后才进入项目经营统计。
4. 员工仍能用最短路径完成工时填报和查看审批结果。
5. 系统管理员可以按模块配置人员权限，不依赖代码发布。

### 4.2 SMART 关键结果

| 关键结果 | 衡量方式 | 目标 |
|---|---|---|
| 项目数据可追溯 | 项目经营指标可下钻到合同、阶段、合同收付款单或工时 | 100% 可追溯 |
| 到期提醒及时 | 到期或逾期事项生成提醒并记录发送结果 | 计划任务执行后 10 分钟内 |
| 审批口径一致 | 未审批收付款不进入项目实际收入或外部成本 | 100% |
| 权限隔离 | 非授权人员无法通过页面或接口访问敏感财务数据 | 100% |
| 数据迁移安全 | v2.0 项目、工时、人员成本和权限数据保留 | 0 丢失 |
| 首页效率 | 常用动作可从工作台直接发起 | 不超过 2 次点击 |

## 5. 目标用户与任务

| 用户 | 主要任务 | 默认数据范围 |
|---|---|---|
| 员工 | 填报工时、查看审批状态、处理驳回 | 自己的工时 |
| 工时审批人 | 审批项目工时、查看已审批记录 | 分配给自己的审批任务 |
| 项目负责人 | 查看负责项目概况，维护项目、合同、阶段，发起收付款，处理提醒 | 自己负责的项目 |
| 出纳 | 审批合同收款单和合同付款单，核对账户、日期、金额和凭证 | 待本人审批及已审批单据 |
| 项目管理人员 | 管理被授权项目、客户、供应商和项目台账 | 授权部门或全部项目 |
| 经营管理人员 | 查看所有项目经营看板和预警 | 权限配置范围 |
| 系统管理员 | 管理组织同步、人员成本、管理员权限和基础配置 | 全系统管理配置 |

约束条件：

- 所有人员选择均来自飞书组织架构。
- 所有金额字段使用人民币元和两位小数，v3.0 暂不支持多币种核算。
- 银行账号、营业执照等敏感信息只向有权限人员展示。
- 项目负责人只能查看负责或明确授权的项目；拥有“全部项目”权限的用户可查看全部项目。

## 6. 价值主张

### 6.1 项目负责人

- 不再分别查询工时、合同和收付款台账。
- 首页直接看到预算执行、人员成本、应收应付和到期提醒。
- 每一条预警可以直接跳转到对应合同阶段或审批单。

### 6.2 员工与审批人

- 工时流程保持简洁，不因新增财务模块增加填报步骤。
- 工作台同时提供填报入口、审批入口和状态反馈。

### 6.3 出纳与管理人员

- 收付款必须关联项目、合同和阶段，审批后自动核销。
- 金额、账户和凭证保留快照，后续供应商资料变化不影响历史单据。
- 权限和审计记录降低误操作和越权查看风险。

## 7. 解决方案

### 7.1 总体信息架构

```text
综合项目管理系统
├─ 工作台
│  ├─ 项目负责人工作区（按角色显示）
│  └─ 员工工作区
├─ 工时管理
│  ├─ 我的工时
│  ├─ 工时审批
│  ├─ 工时看板
│  └─ 工时台账（有权限时显示）
├─ 项目管理
│  ├─ 项目管理
│  ├─ 项目合同
│  ├─ 合同收款
│  ├─ 合同付款
│  ├─ 项目看板
│  ├─ 供应商管理
│  └─ 客户管理
└─ 系统管理
   ├─ 人员成本
   ├─ 集成与通知
   ├─ 管理员管理
   └─ 基础配置
```

人员成本建议归入系统管理。它属于敏感基础数据，由系统管理员授权维护，但会被项目成本计算使用。

### 7.2 工作台

工作台分为上下两部分，并根据当前用户角色自动隐藏无关区域。

#### 7.2.1 项目负责人工作区

仅当当前用户负责至少一个项目或拥有项目经营查看权限时显示。

核心指标：

- 负责项目数量。
- 正常、预警、超预算项目数量。
- 待审批工时数量和涉及工时天数。
- 7 天内到期应收、应付金额。
- 已逾期应收、应付金额。

项目概况按类型展示：

| 项目类型 | 默认展示重点 |
|---|---|
| 研发项目、课题项目、观摩项目 | 人天预算、已发生人天、人员成本、外部付款、应付、成本预算执行 |
| 实施项目 | 同时支持收入合同和支出合同；展示预算与人员成本、外部付款与应付、收入合同额、已收与应收、收付款进度和毛利 |

负责人待办：

- 待审批工时。
- 待提交或待补充的合同收付款单。
- 即将到期和已逾期的应收、应付阶段。
- 项目预算、人天或成本超限预警。

快捷操作：

- 发起合同付款。
- 增加收款。
- 填报工时。
- 处理工时审批。

按钮按权限和项目类型显示。实施项目同时提供“发起合同付款”和“增加收款”；研发类项目默认不显示“增加收款”，但仍可发起支出合同付款。

#### 7.2.2 员工工作区

所有员工显示：

- 本月工时审批单据数量。
- 待审批条数。
- 已驳回待修改条数。
- 草稿条数。
- 最近工时和审批时间线。
- “填报工时”主入口。

### 7.3 工时管理

#### 7.3.1 我的工时

沿用现有单条填报、草稿、提交、驳回修改和详情查看能力。单位固定为天，同一个人在同一天不得重复填报，日期范围不得跨月。

#### 7.3.2 工时审批

沿用“待我审批 / 已审批”双 TAB 和飞书卡片提醒。审批通过的工时进入项目已发生人天和人员成本；驳回工时不进入统计。

#### 7.3.3 工时看板

只保留工时相关内容：

- 工时总量、填报人数、涉及项目数、待审批数量、审批通过率。
- 部门、人员、项目、项目类型、工作阶段、审批状态和时间趋势。
- 工时明细查看与导出。

移除成本预算、实际人工成本、项目成本预算、毛利和资金类指标。这些内容迁移至项目看板。

#### 7.3.4 工时台账

保留现有后台工时管理能力，改名为“工时台账”。仅有权限人员可按日期、部门、人员、项目和状态筛选、分页、修改草稿或异常数据、删除允许删除的记录。

### 7.4 项目管理

#### 7.4.1 项目管理主页面

列表只展示项目主信息：

- 项目名称。
- 项目编号。
- 项目状态。
- 项目类型。
- 项目负责人。
- 所属部门。
- 客户。
- 是否允许工时填报。
- 操作入口。

主列表不展示预算、已发生人天、成本、应收应付和毛利，避免横向信息过载。

项目查看/编辑页使用分区或 TAB：

1. 基本信息：可编辑项目主信息。
2. 人员与工时：可编辑审批人、上级领导、是否可填报；查看项目工时明细。
3. 预算：可编辑人天预算、成本预算和费用预算。
4. 合同与资金：查看关联收入/支出合同、收付款进度。
5. 经营概况：只读展示收入、成本、应收、应付、已收、已付、毛利和预警。
6. 操作记录：查看项目关键变更和审批审计。

#### 7.4.2 项目合同

合同分为收入合同和支出合同两个 TAB。一个项目可以有多个收入合同和多个支出合同。实施项目必须同时允许创建收入合同和支出合同，收入合同用于对甲收款，支出合同用于对供应商或其他付款对象付款。

核心能力：

- 选择项目和客户或供应商。
- 填写合同编号、名称、金额、签订日期、有效期和附件。
- 设置多个收款或付款阶段。
- 每个阶段填写阶段名称、计划金额、计划日期和提醒规则。
- 阶段金额合计必须等于合同金额后才能生效。
- 已产生收付款的阶段不能删除，金额不能调整到低于已收或已付金额。

#### 7.4.3 合同收款

合同收款单必须选择收入合同和具体收款阶段。核心字段包括收款日期、金额、付款方银行账户、公司收款账户、银行流水号和收款凭证。

状态流程：

```text
草稿 → 待出纳审批 → 已确认
                   ↘ 已驳回 → 修改后重新提交
已确认 → 冲销申请 → 已冲销
```

已确认合同收款单：

- 计入项目收入。
- 增加项目已收。
- 核减对应阶段应收。
- 写入不可覆盖的项目经营流水和审计记录。

#### 7.4.4 合同付款

合同付款单必须选择支出合同和具体付款阶段。选择供应商后自动带出收款户名、开户行和银行账号，发起人可以在本单中修改，保存时形成快照，不反向覆盖供应商资料。

状态流程与合同收款单一致。已确认合同付款单：

- 计入项目外部成本。
- 增加项目已付。
- 核减对应阶段应付。
- 与已审批工时产生的人员成本共同组成项目总成本。

#### 7.4.5 项目看板

默认只显示当前用户负责的项目。拥有“查看全部项目”权限的用户可以切换全部项目，并按项目、类型、状态、部门、负责人、客户和日期筛选。

核心指标：

- 收入。
- 人员成本、外部成本和总成本。
- 应收、应付。
- 已收、已付。
- 毛利和毛利率。
- 人天预算执行率和成本预算执行率。
- 到期、逾期和超预算预警数量。

支持从指标下钻到合同阶段、合同收付款单或工时明细。

#### 7.4.6 供应商管理

维护供应商核心资料、联系人、营业执照和默认收款账户。停用供应商不能用于新合同，但历史合同和合同付款单继续显示快照。

#### 7.4.7 客户管理

维护客户核心资料、联系人、营业执照和开票/往来信息。停用客户不能用于新项目或新合同，但历史数据保留。

### 7.5 系统管理

#### 7.5.1 人员成本

保留现有按部门、人员筛选和分页维护单天成本的功能。v3.0 暂不增加成本生效日期，审批通过工时按当前已确认口径计算人员成本。

为避免历史数据随人员单价变化，v3.0 新产生的项目人员成本必须在工时审批通过时保存单天成本和计算金额快照。历史数据按迁移规则补齐。

#### 7.5.2 集成与通知

保留组织同步、飞书连接状态、通知记录和重试。新增合同到期、应收应付、合同收付款审批和预算预警通知类型。

#### 7.5.3 管理员管理

在现有模块权限上增加：

- 工时台账。
- 项目管理。
- 项目合同。
- 合同收款。
- 合同付款。
- 项目看板。
- 查看全部项目。
- 供应商管理。
- 客户管理。
- 人员成本。
- 出纳审批。
- 集成与通知。
- 管理员管理。
- 基础配置。

权限同时在前端菜单和后端接口校验。未配置人员不显示在管理员列表。

#### 7.5.4 基础配置

保留现有项目类型、项目状态、项目阶段、工时类型和执行状态，新增：

- 合同业务分类。
- 收款方式、付款方式。
- 公司银行账户。
- 收付款阶段模板。
- 提醒提前天数和重复提醒规则。
- 客户、供应商状态标签。

审批状态、合同类型、合同收付款单状态等会影响业务逻辑的固定状态不允许管理员随意新增或删除，只允许配置显示名称。

### 7.6 核心业务口径

v3.0 采用项目经营现金口径，不替代会计准则：

| 指标 | 计算口径 |
|---|---|
| 收入合同额 | 已生效收入合同金额合计 |
| 支出合同额 | 已生效支出合同金额合计 |
| 应收 | 已到期收入阶段金额 - 对应阶段已确认收款 |
| 应付 | 已到期支出阶段金额 - 对应阶段已确认付款 |
| 已收 | 已审批确认且未冲销的合同收款单金额 |
| 已付 | 已审批确认且未冲销的合同付款单金额 |
| 收入 | 已收；v3.0 暂按实际到账确认项目收入 |
| 人员成本 | 已审批工时天数 × 工时审批通过时的人员单天成本快照 |
| 外部成本 | 已付；v3.0 暂按实际付款确认外部成本 |
| 总成本 | 人员成本 + 外部成本 |
| 毛利 | 收入 - 总成本 |
| 毛利率 | 收入大于 0 时，毛利 ÷ 收入 |

未到期阶段单独显示为“未来应收/未来应付”，不计入当前应收应付。部分收付款允许存在，阶段状态按剩余金额自动变化。

### 7.7 通知与提醒

- 合同阶段默认在到期前 7 天、3 天、当天提醒项目负责人。
- 到期未完成时标记逾期，并在每个工作日提醒一次，直到完成、取消或人工暂停提醒。
- 合同收付款单提交后通知出纳角色；审批结果通知发起人和项目负责人。
- 工时审批继续通知实际审批人。
- 所有通知保存幂等键、发送时间、飞书消息 ID、失败原因和重试次数。

### 7.8 安全和审计

- 银行账号默认脱敏，仅有收付款编辑、审批或往来单位管理权限的人员可查看完整值。
- 营业执照和凭证附件放入 NAS 持久化数据卷，访问必须经过登录和权限校验。
- 已审批收付款不能直接编辑或删除，只能发起冲销并保留原记录。
- 金额使用十进制定点类型，禁止使用浮点数计算。
- 所有新增、编辑、提交、审批、驳回、冲销、阶段变更和权限变更写入审计日志。

### 7.9 技术方案摘要

- 保留 Vue 3 + FastAPI + SQLAlchemy + NAS Docker 的部署形态。
- 将现有单文件前后端按工时、项目、合同、资金、往来单位、权限和通知拆分模块。
- 保留 SQLite 作为当前 NAS 单实例数据库，启用事务和 WAL；数据规模或并发增加后再迁移 PostgreSQL。
- 使用独立经营流水表保存审批后不可覆盖的金额变化，所有汇总均可从流水重算。
- 使用持久化计划任务扫描到期阶段并发送飞书消息，重复执行必须幂等。

### 7.10 假设和待确认事项

以下事项必须在开发前确认：

1. 是否确认采用“实际收款确认收入、实际付款确认外部成本”的项目经营现金口径。
2. 是否允许一份合同关联多个项目。当前方案限定一份合同只属于一个项目。
3. 是否允许部分收款、部分付款。当前方案允许同一阶段多次收付。
4. 出纳本人发起的收付款是否允许本人审批。建议不允许，并配置一名备用出纳审批人。
5. 收付款冲销是否仍由出纳审批。当前方案要求审批。
6. 研发、课题、观摩项目是否全部禁止收入合同和收款。当前方案只在界面默认隐藏，但可由项目类型能力配置开启；实施项目固定支持收入合同和支出合同，不允许关闭其中一类。
7. 工作日和节假日是否需要接入日历。当前提醒按自然日，逾期后按工作日需增加日历配置。
8. 是否需要发票管理。当前版本不包含发票和税务核算。

## 非目标

- 不直接连接银行或发起转账。
- 不替代财务会计总账，不生成会计凭证。
- 不做发票查验、税务、采购、库存、工资和财务总账；本期仅管理项目费用单及其发票附件。
- 不支持多币种和汇率损益。
- 不提供任意拖拽式 BPMN；采用版本化流程模板和动态审批岗位覆盖项目合同付款与费用审批。
- 不在本版本实现人员成本生效日期。

## 确认门禁

本 PRD、交互设计和系统设计全部确认后才能开始编码。任何财务口径、审批角色和冲销规则未确认时，不允许先做数据库实现。

## 10. v3.0.44 项目费用与审批工作流扩展

v3.0.44 规划新增“项目费用”，覆盖差旅费用、无合同发票费用和其他费用，并将现有合同付款接入统一的多级审批机制。工作流不写死人员，采用“流程模板 + 审批岗位 + 飞书直属上级 + 项目审批人”的动态解析方式；提交时固化流程版本和实际审批人快照。

费用审批通过后计入项目成本，需要支付的单据进入待支付状态；出纳确认支付后增加项目已付，不重复确认成本。详细字段、流程、权限、页面、接口和验收标准见 [41-project-expense-workflow-design-v3.0.44.md](41-project-expense-workflow-design-v3.0.44.md)。该内容当前为设计范围，不代表生产已实现。

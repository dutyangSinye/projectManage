# 收付款附件与合同草稿保存说明

- 版本：v3.0.16
- 日期：2026-09-01
- 状态：已实现并完成回归
- 适用系统：综合项目管理系统

## 背景

收款单和付款单在提交审批前后都需要保留合同、发票、回单等业务材料，但当前只有合同支持附件。合同新建流程已有草稿状态，却缺少明确的保存草稿操作入口。本版本补齐这两个交互和数据能力，沿用合同附件的预览体验。

## 需求范围

| 模块 | 改动 | 验收标准 |
| --- | --- | --- |
| 收款单 | 新增/编辑单据支持附件 | 单据保存后可上传多个附件；列表显示文件名、类型、大小和时间；支持预览、下载、删除；未保存时明确提示先保存单据 |
| 付款单 | 新增/编辑单据支持附件 | 与收款单附件交互一致，附件只归属当前付款单，不与合同附件混淆 |
| 附件预览 | 复用合同附件模式 | Word、Excel、PPT、PDF、图片可预览；转换或预览失败时可下载原文件；单个文件最大 50MB |
| 合同 | 新增合同支持保存草稿 | 新建/编辑合同底部提供“保存草稿”和“保存合同”；保存草稿强制使用 `DRAFT` 状态，并在保存成功后仍可继续上传附件 |

## 业务规则

1. 收付款附件使用独立的 `cash_document_attachments` 表，通过 `document_type` 区分 `RECEIPT` 和 `PAYMENT`，通过 `document_id` 绑定单据。
2. 附件上传必须先保存收款单或付款单取得单据 ID；新增单据保存成功后保留表单弹窗，用户可直接继续上传附件。
3. 收付款附件的查看、上传、删除遵循对应单据的项目数据范围和收款/付款管理权限；审批人查看审批详情时可以读取附件。
4. 删除附件只删除当前附件元数据和文件本体，不影响单据、合同或审批记录。
5. 合同草稿仍校验项目、往来单位等基本识别字段；草稿不计入正式经营数据，附件可在草稿阶段上传。
6. 收付款附件和合同附件共用文件类型识别与 Office 转 PDF 预览逻辑，但接口和数据表保持隔离。

## 接口契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/receipts/{receipt_id}/attachments` | 查询收款单附件 |
| POST | `/api/v1/receipts/{receipt_id}/attachments` | 上传收款单附件 |
| GET | `/api/v1/payments/{payment_id}/attachments` | 查询付款单附件 |
| POST | `/api/v1/payments/{payment_id}/attachments` | 上传付款单附件 |
| GET | `/api/v1/cash-attachments/{attachment_id}/preview` | 预览收付款附件 |
| GET | `/api/v1/cash-attachments/{attachment_id}/download` | 下载收付款附件 |
| DELETE | `/api/v1/cash-attachments/{attachment_id}` | 删除收付款附件 |

上传接口使用 `multipart/form-data` 的 `file` 字段，返回与合同附件一致的附件视图字段。

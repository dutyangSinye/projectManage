# 项目费用与动态审批工作流实施说明

- 版本：v3.0.45
- 日期：2026-09-06
- 状态：已开发、已测试、已发布
- 对应生产版本：v3.0.45
- 上游设计：`41-project-expense-workflow-design-v3.0.44.md`

## 1. 本次范围

本版本将 v3.0.44 已确认的高保真原型落到生产系统，并追加两项确认修订：

1. 全系统显示术语统一使用“人天预算”，不再显示“预算人天”或“预算人天数”；数据库与 API 字段 `budget_days` 保持兼容，不做破坏性重命名。
2. 项目新增、编辑和预算详情增加独立“费用预算”字段，数据库与 API 字段为 `expense_budget`。
3. 新增项目费用台账、三类费用表单、附件、详情、审批、支付和项目成本归集。
4. 新增审批岗位、流程定义、不可变流程版本、流程节点、审批实例、任务和操作记录。
5. 合同付款接入七级动态审批；收款继续使用现有出纳审批，避免改变已确认边界。
6. 增加项目费用、审批岗位、审批流程权限资源以及飞书审批通知。

## 2. 预算口径

| 指标 | 含义 | 计算方式 |
| --- | --- | --- |
| 人天预算 | 项目允许投入的人天额度 | 管理员维护，已审批工时占用 |
| 成本预算 | 项目全部成本控制额度 | 人员成本 + 合同成本 + 项目费用成本 - 冲销 |
| 费用预算 | 差旅、无合同发票和其他费用的子预算 | 已审批项目费用成本 - 费用成本冲销 |
| 费用预算剩余 | 尚可使用的项目费用额度 | 费用预算 - 已审批项目费用成本 |
| 费用预算使用率 | 项目费用占费用预算比例 | 已审批项目费用成本 / 费用预算 |

费用预算是成本预算的分析维度，不作为成本金额相加。费用预算为零时显示“未设置预算”，不产生错误百分比。超预算首期允许继续提交但明确提示，由审批链决定是否通过。

## 3. 核心状态与流程

- 费用单：`DRAFT -> PENDING_APPROVAL -> APPROVED_PENDING_PAYMENT / APPROVED -> PAID`，驳回为 `REJECTED`，冲销为 `REVERSED`。
- 差旅费用：项目审批人 -> 上级领导 -> 会计 -> 总经理 -> 出纳支付。
- 无合同发票、其他费用、合同付款：项目审批人 -> 经营审批 -> 上级领导 -> 经营副总 -> 会计 -> 总经理 -> 出纳支付。
- 项目审批人等于申请人时改由直属上级处理；相邻重复审批人自动通过；出纳节点永不自动通过。
- 或签岗位全部候选人收到待办与飞书通知，任意一人处理后关闭同节点其余任务。

## 4. 数据与接口增量

新增表：`project_expenses`、`project_expense_attachments`、`project_expense_payments`、`approval_positions`、`approval_position_members`、`workflow_definitions`、`workflow_versions`、`workflow_nodes`、`workflow_instances`、`workflow_tasks`、`workflow_action_logs`。

项目表新增：`expense_budget NUMERIC(14,2) NOT NULL DEFAULT 0`。

项目分析返回新增：费用成本、费用预算、费用预算剩余、费用预算使用率以及按月费用成本。项目总成本统一为人员成本、合同成本和项目费用成本之和。

接口沿用上游设计第 14 节，并增加费用附件上传、预览、下载、删除接口。所有写接口执行后端权限、数据范围、状态和金额校验。

## 5. 关联影响与回归范围

- 项目管理：新增/编辑、详情预算、列表字段和术语。
- 项目费用：列表、筛选、分页、草稿、附件、预检、提交、审批、支付、驳回和冲销。
- 项目详情与项目看板：成本组成、总成本、预算剩余、毛利和费用下钻。
- 合同付款：新提交单据使用七级流程，历史单据保持原审批记录可读。
- 管理员管理：新增菜单和按钮操作权限。
- 集成与通知：费用审批节点、结果和支付通知记录及重试。
- 飞书登录、组织同步、工时、合同、收款、现有附件和导出必须保持正常。

## 6. 准出标准

1. 数据库从旧版本启动可自动增加字段和新表，不删除或重算历史数据。
2. 三类费用完整走通保存草稿、附件、提交、逐级审批、支付和成本归集。
3. 审批岗位为空、项目审批人缺失或直属上级缺失时阻止提交并给出明确错误。
4. 权限与数据范围在前后端同时生效，直接调用无权接口返回 403。
5. 项目总成本和费用预算计算可逐笔与流水对账，重复审批不重复记账。
6. 前端构建、后端测试、核心接口回归和桌面页面检查全部通过。
7. 发布前备份服务器应用目录；数据库 Docker 卷不覆盖；发布后健康检查和线上主流程通过。

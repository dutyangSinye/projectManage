# 综合项目管理系统 v3.0.38：飞书 SDK 初始化兜底

- 版本：v3.0.38
- 日期：2026-09-05
- 状态：已确认，进入实现

## 1. 问题

在部分飞书内置浏览器中，`h5sdk.ready` 不触发回调，但页面已经提供 `tt.requestAuthCode` 授权方法，导致登录流程卡在“正在打开飞书授权…”阶段。

## 2. 方案

- 保留 `h5sdk.ready` 正常初始化路径。
- 如果初始化回调在 1.5 秒内没有触发，且授权方法已经存在，则直接启动标准 `requestAuthCode`。
- 使用单次启动保护，避免 SDK 回调和兜底同时发起两次授权。
- 继续保留 8 秒总超时，任何异常都结束加载并显示明确提示。

## 3. 验收标准

1. `h5sdk.ready` 正常回调时只发起一次授权。
2. `h5sdk.ready` 不回调但授权方法已存在时，1.5 秒内进入授权调用。
3. 授权方法也未加载时，最终显示环境/加载失败提示。
4. 不发生重复授权调用，不改变后端换码和登录逻辑。

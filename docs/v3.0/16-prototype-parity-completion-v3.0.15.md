# 原型差异补齐说明

- 版本：v3.0.15
- 日期：2026-09-01
- 状态：已实现并完成回归
- 适用系统：综合项目管理系统

## 背景

上一轮已经补充了部分接口和页面入口，但仍有“能访问”而不能完成业务核对的问题。本轮以原型差异清单为验收基线，重点补齐数据上下文、页面联动、详情下钻和可操作状态，不改变既有审批口径和飞书通知口径。

## 本轮实现范围

| 模块 | 要实现的行为 | 验收标准 |
| --- | --- | --- |
| 集成与通知 | 集成概况、组织同步时间线、通知策略、统一通知中心 | 可看到连接状态、组织人数、今日发送、失败待处理、新增/更新统计；同步记录可分页；策略可保存；通知可按类型/状态分页、看详情、看失败原因、重试 |
| 项目详情 | 六个主页签和合同资金三类关联视图 | 经营分析、基本信息、人员与工时、预算、合同与资金、操作记录均有明确内容；合同与阶段、收款单、付款单可从项目内直接核对并下钻 |
| 项目看板 | 经营汇总、毛利排行、收付款趋势、应收/应付账龄、预警下钻 | 图表与筛选数据一致；项目名称、图表项目和预警均可进入项目详情；无数据、加载、失败状态明确 |
| 合同管理 | 主信息与阶段分离、合同详情一站式展示 | 合同列表只展示主信息；点击合同名称进入详情后直接显示结算率、收付款单笔数、阶段、附件和阶段余额 |
| 收付款管理 | 收付款单完整详情与审批 | 详情展示项目、合同、阶段、客户/供应商、账户、金额、阶段计划/已收已付/剩余、审批时间线；审批前二次确认；审批后刷新列表和详情 |

## 设计约束

- 业务状态以本地审批状态为准；飞书负责组织同步和消息通知。
- 已审批收款/付款才计入已收/已付；应收/应付只统计已到期阶段未收/未付金额。
- 页面保持现有浅色业务系统风格，不引入 Element Plus。
- 所有详情入口使用同一套按钮和返回路径；弹窗点击遮罩不误关闭表单。

## 回归范围

编码后必须执行：前端生产构建、后端测试与编译、集成页关键接口、项目详情六页签、合同/阶段维护、合同收付款审批与通知、项目看板图表/下钻、管理员权限、桌面端和 390×844 移动端布局回归。

## 回归结果

- 前端 `pnpm run build` 通过；修复项目看板首次进入时图表初始化与认证加载态之间的竞态，5 个图表会在内容态出现后自动渲染。
- 后端标准库 `unittest` 19 条全部通过，包含项目 CRUD、合同阶段金额校验、合同收付款审批入账、应收账龄口径、通知中心接口和附件预览类型。
- 集成与通知、项目详情、项目看板、合同管理、收款管理、付款管理在桌面端和 390×844 移动端完成页面回归，无页面级横向溢出。
- 集成通知中心已验证类型/状态筛选、通知详情入口和统一记录展示；合同详情已验证主信息、结算率、单据数、阶段和附件区域直出；收款详情已验证项目、合同、阶段、账户和审批时间线直出。

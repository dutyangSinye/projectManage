# Asia/Shanghai 时间规范

## 版本信息

- 版本：v3.0.19
- 日期：2026-09-01
- 状态：已实现

## 目标

统一综合项目管理系统的应用时区为 `Asia/Shanghai`，解决容器时区、后端 `datetime.utcnow()`、前端 UTC 日期和历史记录显示不一致的问题。

## 设计

- 后端使用 `ZoneInfo("Asia/Shanghai")` 生成应用时间，数据库现有 `DateTime` 字段继续保存无时区的上海本地时间，避免改表造成兼容风险。
- 现有 SQLite 数据库首次启动升级时，将旧版本按 UTC 写入的时间字段统一加 8 小时，并使用 `PRAGMA user_version` 保证迁移只执行一次。
- 后端业务日期统一使用上海本地日期，包含工时默认日期、单据编号、报表查询默认日期、提醒扫描和日期边界判断。
- 前端日期默认值和时间展示显式使用 `Asia/Shanghai`，不依赖访问者浏览器时区。
- NAS backend Docker 服务增加 `TZ: Asia/Shanghai`，保证系统命令、日志和 Python 运行环境时区一致。

## 影响范围

- 工时、审批、收付款、合同附件、组织同步、通知、审计、报表生成时间。
- 不改变业务日期字段的含义和金额、人天、审批状态计算逻辑。

## 验证标准

- 后端源码不再使用 `datetime.utcnow()` 生成业务时间。
- 本机和容器时区均为 `Asia/Shanghai`。
- 新建记录时间与上海当前时间一致，旧记录只完成一次 +8 小时修正。
- 前端日期默认值、时间详情和通知时间在非上海浏览器环境下仍显示上海时间。
- 前端构建、后端编译和时间工具单元测试通过。
